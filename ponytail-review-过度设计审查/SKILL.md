# ponytail-review

只找"多余"。三种模式共用同一套 tag 与输出契约，差别只在扫描范围。

> **合并说明**：本技能由三个上游技能收敛而来——原 `ponytail-review`（diff 审查）为主体，吸收 `ponytail-audit`（整仓审计，现为模式二）与 `ponytail-debt`（`ponytail:` 注释台账，现为模式三）。三者的 tag 与输出契约本就一致，合并后只保留一处权威来源，避免同一套规则在三份文件里各写一遍。

## 模式路由

| 用户说法 | 模式 | 扫描范围 | 细节 |
|---|---|---|---|
| "review 一下这段改动/这个 PR"、默认情况 | **diff 审查** | 当前改动 | `references/diff-review.md` |
| "审计这个仓库"、"哪里臃肿"、"能删掉什么" | **全库审计** | 整个代码库 | `references/repo-audit.md` |
| "ponytail 债务"、"我之前推迟了什么" | **债务台账** | `ponytail:` 注释 | `references/debt-ledger.md` |

用户没说清楚时默认走 diff 审查；若工作区没有改动（无 diff 可看），直接切全库审计并说明切换原因。

## 输入

- diff 模式：当前工作区改动（或用户指定的 commit/分支范围）。
- 全库模式：仓库根目录；用户可指定要跳过的目录。
- 债务模式：仓库根目录 + 该项目的注释前缀（默认 `#` 与 `//`）。

## 输出

每个发现一行，**先给最大的删减项**：

```
<tag> <该删什么>. <用什么替代>. [位置]
```

位置格式：单文件 `L<行号>`；多文件或全库 `<路径>:L<行号>`。

结尾必须给唯一指标：`net: -<N> lines possible.`
没有可删的：`Lean already. Ship.`（债务模式则是 `No ponytail: debt. Clean ledger.`）然后停止。

## 步骤

1. 判断模式，读对应 references 文件后再动手。
2. 按该模式的扫描清单收集候选。
3. 每个候选用五个 tag 之一归类：`delete:` / `stdlib:` / `native:` / `yagni:` / `shrink:`。
4. 套输出契约：一行一条，写清替代方案（没有替代就写 `Nothing replaces it.`）。
5. 按删减量从大到小排序，结尾一句 `net:`。

五个 tag 的判定标准（全模式共用）：
- `delete:` 死代码、没人用的灵活性、投机功能。替代：无。
- `stdlib:` 手写的、标准库已有的东西。必须点名函数。
- `native:` 依赖或代码在做平台本来就做的事。必须点名那个平台特性。
- `yagni:` 只有一个实现的抽象、没人设的配置、只有一个调用方的层。
- `shrink:` 同样逻辑、更少行数。给出更短的写法。

## 坑点

- **不要把最小测试算成臃肿**：单个冒烟测试或 `assert` 自检是 ponytail 的底线，不是冗余，禁止建议删除。
- **不要越界**：正确性 bug、安全漏洞、性能问题明确不在范围内，指路常规 review，不要顺手改。
- **不要给空泛建议**："这个类可能有点复杂，你考虑下是否必要？"是反面样本；必须给出可执行的一句替代。
- **不要自动改代码**：只列清单。用户明确要求时才动手，且只在其确认的条目上动手。
- **全库模式不要只看文件数**：排名依据是"删掉能减多少行/多少依赖"，不是文件大小。

## 验证

交报告前自查：
- [ ] 每条都带 tag、位置、替代方案三要素，无一句空话。
- [ ] 结尾有 `net: -<N> lines possible.` 或明确的"无需改动"结论。
- [ ] 没有越界到正确性/安全/性能。
- [ ] 没有把最小自检当作可删项。
- [ ] 全库模式确认已跳过 `node_modules`、`.git`、构建产物。

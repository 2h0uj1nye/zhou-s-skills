# 债务台账细则

ponytail 会把每个刻意的简化用 `ponytail:` 注释标出来，注明天花板与升级路径。
本模式把这些注释收成一张台账，避免"以后再说"变成"永远不说"。

## 扫描

```bash
grep -rnE '(#|//) ?ponytail:' . | grep -v node_modules | grep -v '\.git/'
```

（栈里用别的注释前缀就再补几个。）命中的每一行就是台账的一行；注释前缀本身把"只是提到这个约定"的正文挡在台账之外。

## 台账格式

按文件分组，一行一条：

```
<文件>:<行号>, <被简化了什么>. ceiling: <注释里写的天花板>. upgrade: <什么时候该回头>
```

约定是 `ponytail: <天花板>, <升级路径>`，天花板与触发条件直接从注释里取。
需要责任人时再加 `git blame -L<行号>,<行号>`。

## 腐化标记

任何没有写升级路径/触发条件的 `ponytail:` 注释打上 `no-trigger` 标签——这些就是会悄悄烂掉的那批。

结尾：`<N> markers, <M> with no trigger.`
没找到：`No ponytail: debt. Clean ledger.`

## 边界

只读、只报告，不修改任何文件。用户要求落盘时才写出台账文件（如 `PONYTAIL-DEBT.md`）。一次性执行。

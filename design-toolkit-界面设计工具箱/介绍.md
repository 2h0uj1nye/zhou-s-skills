# 界面设计工具箱（design-toolkit）

> 一句话：让 AI 做的网页不再是那种一眼能看出是 AI 做的"模板脸"——它管三件事：出一个能打开的成品页面、出几个思路不同的方案让你挑、审你现有的页面到底哪里不对。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；验证环节会调用 DSH 自带浏览器工具 `browser_open` / `browser_screenshot`） |
| 外部依赖 | 零依赖，不装框架、不需要 API key；只有"从网址抽设计风格"时需要联网打开那个网址 |
| 产出 | A：单个自成一体、双击就能打开的 HTML 文件（组件时附八态预览页）；B：2-3 个变体 + 一张正面对比表；C：分级问题清单或结构化风格诊断报告 |
| 入选理由 | 罕见地把"好不好看"落成**可判定**的门：编号硬门 + AI 味打分 + 能直接跑的 grep 自查命令，并强制"先诊断、后治疗" |

## 它解决什么问题

你让 AI 做个落地页，它给的永远是同一套：居中大标题 + 三张权重相同的图标卡 + 蓝紫渐变——问题不在配色，在**构图根本没做决定**。
另外两个常见毛病：你只想对比一个方案，它只给一个就完事；你说"这页面哪里有问题"，它直接推倒重做，你还得从零验收。这个技能针对这三点：先定骨架再动颜色、一次给多个立场、审计时只出清单不动文件。

## 什么时候该用它

- "帮我做个落地页 / 看板 / 原型 / HTML 演示页 / 一个按钮组件。"
- "给我两三个不同方向的方案，我看看再定。"
- "这个页面设计有什么问题？帮我评一下。"
- "照这张截图（或这个网址）的风格，把我们的页面改成那种感觉。"

## 什么时候别用它

- 你只想写或校验 `DESIGN.md` 这个设计令牌规范文件——那是 `design-md`，别在这里自建规范。
- 你要做 PPT / 演示文稿——那是 `univer-slide`。
- 你要后端、数据库、业务逻辑——它只做前端界面。

## 怎么开口

- "帮我做个 SaaS 产品的定价页，给产品和销售看。"
- "给我三种不同风格的首屏方案，附上对比表。"
- "看看我这个页面有什么毛病，先别改。"

## 输入 / 输出

**它会向你要：** 模式（成品 / 变体 / 审计）、目标和受众、已有的设计系统文件（有就必须真读，不许凭记忆编）、素材（真实文案与图片，缺了用占位符并标"待确认"）、可选参考截图或网址。需求太空时它**只问一次**三个问题：受众是谁、页面要驱动哪一个动作、调性挑一个极端（editorial / brutalist / soft / utilitarian / luxury / playful / technical / austere）——"简洁现代"这种答案它不认。

**最后给你（按模式不同）：**
- **A 成品**：一个自包含 HTML 文件（CSS 在 `<style>`、JS 在 `<script>`，文件名描述性）；组件范围多给一个八态预览页；结尾固定四行报告：产物路径 / 内容要点 / 验证状态 / 下一步。**B 变体**：2-3 个各成文件的方案（`NNN-立场名/index.html`，各带 README）+ 一张 head-to-head 对比表 + 一句有观点的判断。
- **C 审计**：**只读不改**，给你分级清单（blocker / high / medium / low），每条给位置、问题、修法；抽 DNA 则先出结构化诊断报告，再问你"整套采纳还是换一个轴"。

## 依赖与前提

无外部依赖：产物是单个 HTML 文件，浏览器打开即可，不需要框架或打包工具。审计和抽 DNA 需要你给一张截图或一个能打开的网址；网址打不开（登录墙、纯 JS 空壳、正文太小）时它会降级为截图模式并明说原因。验证环节用宿主自带的浏览器工具，不用另装 Playwright 之类的东西。

## 注意事项与已知限制

- **它会拒绝替你编数据**：用户没给的指标只能写真实数字或占位符（`—` 加灰色块，标"待确认指标"）。`+47% 转化`、`服务 50,000+ 团队`、`快 10 倍` 一旦是编的就算 AI 味，所以商业页面请先准备好真实内容。
- **组件类产物必须给全八个状态**（default / hover / focus / active / disabled / loading / error / success），缺一个就算没做完；**手机端要过 320 / 375 / 414 / 768 四个宽度**，不是"看起来还行"，横向滚动必须用 `overflow-x: clip`、不许用 `hidden`。
- **审计是只读的**，不会顺手帮你改，想修要再开一轮成品模式——这是刻意的，"审计和修复一口气做完"正是它要避免的失败模式。
- **硬门编号有跳号**（34、38a、46-54 等），沿用合并前那套技能的原始编号，不是漏了什么。**需求太空时它只问一次**；如果你回"你定吧"，它会自己推断并把推断写在回复最上面让你改。**它也不会假装做完**：文件没真写出来、没真用浏览器打开过，就不会说 done。
- 它不是设计稿生成器也不是 Figma 替代品，产物是 HTML；真实数据与后端联动不在范围内。

## 来源

由 **3 个上游技能合并**：`claude-design`（做 HTML 产出的流程与品味）+ `sketch`（多变体对比法）+ `hallmark`（页面审计）。`hallmark` 原来配套的**整套 references 在源目录里并不存在**（悬空引用），故未继承，只保留它正文里真正可用且本技能能独立判定的硬规则——AI 味门号、组件八状态、移动端底线，门号沿用原始编号以便回溯；合并后也去掉了 `hallmark` 把"审计"和"修复"混在一起的旧做法（现在审计严格只读）。
这一合并事实在 `SKILL.md` 第 8 行和 `references/anti-slop.md` 第 40 行都有明确文字，可直接核对。

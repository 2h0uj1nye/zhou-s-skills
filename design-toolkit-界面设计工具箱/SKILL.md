# design-toolkit

一套 HTML/界面设计技能，三种模式共用同一套抗 AI 味（anti-slop）标准。合并自 claude-design / sketch / hallmark 三个技能，只保留它们真正可执行的私域规则。

**单一职责**：只做「HTML/界面设计的产出与审计」。令牌规范文件的编写与校验不属于本技能——那是 `design-md` 的职责；演示文稿（PPT/pptx）属于 `univer-slide`。若用户要的是「锁定这套设计系统成 tokens 文件」「校验 DESIGN.md」，直接用 `skill` 加载 `design-md`，不要在本技能里自建令牌规范。

## 一、模式路由（先选模式，再动手）

| 模式 | 触发 | 交付物 | 细读 |
| --- | --- | --- | --- |
| **A · 成品 build** | 做个页面 / 设计界面 / 落地页 / 看板 / 原型 / deck / 组件 / 照这个改 | 单个自包含 HTML 文件（+ 组件时的 8 态预览页） | `references/build.md` |
| **B · 变体对比 variants** | 看看几种方案 / 给我 2-3 版 / 比较布局 / 先出草图再定 | 2-3 个各成文件的变体 + head-to-head 对比表 | `references/variants.md` |
| **C · 审计与抽 DNA audit** | 这个设计有什么问题 / 评一下 / 从这张图或这个网址抽 DNA | 分级问题清单（不改文件）；或结构化 DNA 诊断报告 | `references/audit.md` |

**路由规则**：用户既没给方向又要「先看看」→ B；用户已定方向要可交付产物 → A；用户给的是已有页面 / 截图 / 网址并要评价或提炼 → C；同时要审计又要重做 → 先 C 出清单，用户确认后转 A。

**任何模式开工前都要**：读 `references/anti-slop.md`（硬门在此）。涉及移动端的一律加读 `references/responsive.md`。

## 二、通用硬规则（三模式共用）

### 2.1 Surface-first：先定原型，再定视觉
最高杠杆的一条。AI 设计的味绝大多数是**构图问题，不是配色问题**——每个页面都长成「居中 hero + 三张等权卡片」。调色救不了骨架。

动手写颜色 / 字号 / 组件之前，先**明说**选定的唯一原型：

1. **Monitor** 看状态变化（看板、状态页、可观测）：密度、可扫读，不要营销框架。
2. **Operate** 对事物采取行动（控制台、管理台、队列、收件箱）：动作与选中态主导。
3. **Compare** 比较多个选项（定价、套餐、规格表、搜索结果）：列对齐、结构对等、只强调一个差异点。
4. **Configure** 完成设置（设置、表单、向导、引导）：渐进披露、清晰的保存与校验态、少装饰。
5. **Decide / Learn** 被说服或被教会（落地页、文档、营销）：每节只落一个观点；**这是唯一通常适合放 hero 的原型**。
6. **Explore** 在开放空间里浏览（画廊、地图、筛选、目录）：筛选器、结果网格、缩放预览就是构图本身。
7. **Command / Inspect** 用键盘驱动或钻取单个对象（命令栏、检查器、详情面板、属性编辑器）：速度与专注优先于广度。

硬规则：看板是 Monitor 不是 Decide，不许给它居中 hero + 三张特性卡；一个页面横跨两种原型时点名**主要**那个，不要平均成糊状；「hero + 三卡」只在 Decide/Learn 正确，出现在别处就是第一号 tell。

### 2.2 anti-slop 十条 tell（完整版与打分法见 `references/anti-slop.md`）
tech 渐变 / 默认靛紫强调色 / 三张等权图标卡 / 卡片左侧色条 / 无来由的毛玻璃 / 填空间的巨型数字 / 每个标题上方的圆角图标 / 全部居中 / 默认 Inter 或 system-ui 未经选择 / 原型错配。**先诊断再治疗**：先出 1-10 分报告并点名命中哪几条，再按诊断类别修——构图类（三卡、全居中、原型错配）回炉重排，不要改色；配色排版类才改色改字；装饰类直接删，用层级（尺度、字重、间距）替代。修完重新打分，构图类 tell 还在就不算完成。

### 2.3 诚实内容（安全底线）
用户没给的指标**不许编**。数字型版式、对比行、信任条只能用真实数字、占位符（`—` 加灰色块并标注「待确认指标」），或换一种骨架。`+47% 转化`、`服务 50,000+ 团队`、`快 10 倍` 一旦是编的，立刻算 slop。客户评价、客户 logo、案例数量同理。多写一段文案、多编一个数据若会影响策略或主张，先问用户。

### 2.4 令牌锁定，不许即兴
定完系统后，产物里每个颜色与 `font-family` 都必须引用具名 token（`var(--color-accent)`、`font-family: var(--font-display)`）。内联 OKLCH / hex / `rgb()`，或绕过 token 块直接写字体名，都不允许；需要新值就先把它提升为 token 块里的具名变量再引用。

### 2.5 不许手绘假 chrome
不要手搓假浏览器栏（地址胶囊 + 红黄绿点）、假手机边框、假代码窗口（假标题栏 + 三点包一个 `<pre>`）、假 IDE 外观——用户的运行环境本来就提供真 chrome。用真截图包在 `<figure>` 里（最多一条发丝边框），或者干脆不要 chrome 让内容自己站住。

### 2.6 排版纯净：标题不斜体
标题与展示字体一律正体（`font-style: normal`）。正体标题里挑一个词改斜体（`Built to <em>think</em>`）是最可靠的 AI 味之一，整块斜体展示字体同样是。强调靠字重、强调色、手绘下划线。斜体只允许留在正文段落的行内强调。

### 2.7 结构多样性
两个页面不该共用同一套「hero → 三特性 → CTA → 页脚」节奏。同一项目里的连续输出，**不得复用同一个骨架**。做法：产物第一行注释写 stamp——`/* design-toolkit · surface: <原型> · skeleton: <骨架名> · mode: <模式> · tokens: <来源> */`；下次开工先读项目里已有产物的 stamp，换一个骨架与不同纸张明度 / 展示字体 / 强调色相中的至少一项。默认避开两种最大众化骨架：极简两链接导航 + 四列链接页脚。

## 三、移动端底线（硬地板，不是愿望)

每个产物必须在 **320 / 375 / 414 / 768 px** 四个宽度下无瑕疵。不可协商项（细节与自查命令见 `references/responsive.md`）：

- 无横向滚动；`html` 与 `body` 都用 `overflow-x: clip`，**不许用 `hidden`**（门 34）。
- 可点文本不许折成两行：按钮、主导航项、页脚链接、面包屑、CTA（门 49）。
- 含图片的网格轨道用 `minmax(0, 1fr)`，不许裸 `1fr`（门 50）。
- 展示标题用 `overflow-wrap: anywhere; min-width: 0` 承载超长词（门 51）。
- 区块头在所有主题变体下都塌成单列（门 52）；radio-tab 模式不得滚动跳变（门 53）。
- 移动端点击目标 ≥ 44px。
- 标签在标题上方垂直堆叠；**禁止**标签在左、标题在右的悬挂式两栏（门 54，最可靠的自模板化 tell）。

| 素材 | 视情况 | 真实文案、图片、品牌色；缺失时用占位符并标「待确认」，**绝不**编造 |

## 五、【输出】契约（固定，不许含糊）

### A · 成品
- **一个自包含 HTML 文件**：CSS 在 `<style>`，JS 在 `<script>`，文件名描述性（如 `Landing Page.html`、`Command Palette Prototype.html`）。
- 首页首行 `<style>` 内必须有 stamp 注释（见 2.7）。
- 大改版保留旧版：`Name v2.html`；或单文件内用页内开关做变体探索。
- 组件范围改出两个文件：组件本体（跟随项目技术栈）+ `<Name>.preview.html` 八态预览页（用完即删，不进生产）。
- 结尾报告固定四行：产物路径 / 内容要点 / 验证状态 / 下一步。

### B · 变体对比
- 每个变体一个目录 `NNN-立场名/index.html`，命名描述立场而不是编号。
- 全部变体建完后给 **head-to-head 对比表**（维度 × 变体）**加一句有观点的判断**，不能只罗列。
- 让用户挑一个胜出、或合并成混合体、或再来一轮；用户选定后要收敛，不要把项目永远留成一堆选项。

### C · 审计与 DNA
- 审计：**只读不改**，输出**分级问题清单**（blocker / high / medium / low），每条给位置、问题、修法。
- DNA：先出结构化诊断报告，再问用户「整套采纳还是换一个轴」；不复制像素。

## 六、【步骤】通用工作流

1. **读上下文**（能读就先读，别凭记忆编）：`design.md` / `DESIGN.md`、tokens、主题与全局样式、组件文件、已有截图、品牌文档。文件树只是菜单，决定视觉词汇的文件要真读。
2. **选模式**（第一节表），并明说模式名。
3. **定 surface**（2.1），一句话说出来。
4. **补齐信息或推断**：需求太空时按第八节问；用户说「你定」就推断，并把推断写成一句话放在回复顶部（受众 = X · 用途 = Y · 调性 = Z），错了好改。
5. **出预览块**再写代码（成本最低的纠偏点）：骨架 / 主题（纸张明度 · 强调色相 · 展示字体）/ 装饰层级 / 分节顺序 / 动效 / 已知妥协，各一行。
6. **构建**：OKLCH 颜色、4pt 间距刻度、2+1 字体纪律（展示体 + 正文体，单一等宽体当设计本身时例外）、八态交互、只动 `transform`/`opacity`、具名缓动、`prefers-reduced-motion`、`:focus-visible` 可见环（≥3:1 对比，出现不做动画）。
7. **验证**：见第九节。
8. **报告**：按第五节 A/B/C 对应的固定格式。

## 七、【坑点】

- 把审计和修复一口气做完——模型的先验会压过指令，于是构图问题被当成配色问题去修。**先出报告，再修。**
- 用户已给足方向还追问一堆；或高保真任务毫无品牌上下文却不问。都不行。
- 产出通用 SaaS 布局并称之为「设计完成」。
- 声称做过浏览器验证但实际没做。**文件没真写出来就绝不说「done」。**
- 编造指标、客户、评价、案例数。
- 为凑装饰画复杂假 SVG 插画（除非任务本身就是插画）；用图标堆满卡片。
- 验收移动端只看一个宽度。
- 大文件里硬编码视口假设；点击目标过小；装饰性 JS 与可用性打架。

## 八、【失败处理】

- **需求太空**（如「做个网站」）：一次只问三个问题——① **受众**：谁用、在意什么；② **用途**：这个页面要驱动的那一个动作是什么（注册？订阅？阅读？购买？）；③ **调性**：挑一个极端——editorial · brutalist · soft · utilitarian · luxury · playful · technical · austere，「简洁现代」不算调性。只问一次，三个标签加粗便于扫读；不要层层追问。
- **用户不接话 / 说「你定吧」**：从 brief、领域、可见上下文（文件名、框架、周边代码）推断三项，**必须**把推断明写在回复顶部并说明可纠正；此时仍要挑一个非默认骨架。沉默字段视为放弃，不做二次追问。
- **无法判断品牌调性且没有品牌资产**：默认走 **editorial**（安定的抗 slop 基准），只用一轮里最保守的调色（中性色 + 一个强调色），并把「调性是默认推断」写进预览块第一行，让用户一眼能改。有品牌色/多属性氛围词（三个以上 vibe 词）时才做定制配色。
- **拿不到源素材（真实图片/文案缺失）**：用干净占位符或排版/版式/抽象纹理替代，标注「待确认」；**绝不**把编造的图当成最终设计交付。
- **URL 抓不到**（登录墙、纯 JS 壳、非 2xx、正文 < 1KB）：降级为截图模式并明说降级原因，不要静默退化。
- **写文件失败**：报告失败原因与目标路径，不要谎报完成。

## 九、【验证】与自查清单

写完/审完，逐条自查并在报告里说明「已验证 / 未验证及原因」：

- [ ] 文件真的存在于所报路径，HTML 完整、能在浏览器直接打开。
- [ ] 用 `browser_open` 打开产物，必要时 `browser_screenshot` 看主视口；控制台无报错、无重叠文字、无未样式化元素、无裂图。
- [ ] 交互真的能点：主路径可点、至少一个有意义的状态切换、悬停有反馈。
- [ ] 组件类产物：**八个状态齐全**——default · hover · `:focus-visible` · `:active` · disabled · loading · error · success，每个都有实际样式（细节见 `references/anti-slop.md`）。
- [ ] 颜色与字体**只**引用 token 变量，没有内联 hex/OKLCH/字体名绕过 token（门 48）。
- [ ] 320 / 375 / 414 / 768 四个宽度都无横向滚动（`overflow-x: clip`），可点文本不折两行。
- [ ] 没有出现被禁的假 UI 装饰：假浏览器/手机/代码窗框，标题斜体，悬挂式标签栏。
- [ ] 没有编造指标、客户、评价；所有数字有来源或已标为待确认。
- [ ] anti-slop 复查打分：构图类 tell 已归零；报出分数与命中的 tell。
- [ ] 引用外部设计时已注明来源，且只迁移原则与姿态，没有复制像素或专有布局。

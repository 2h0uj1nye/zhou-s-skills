# anti-slop 硬门与状态清单

这是三个模式共用的判定标准：本文件里的规则是**可判定的**（能指着某一行说"这违反了"，或能跑命令验证）。品味建议不写在这里，写在 `references/build.md`。

---

## 一、先诊断再治疗（工作方式）

AI 设计的失败分布很小且可预测：让人给 AI 界面打"这看起来是 AI 做的"标签时，信号会塌缩成十条 tell。

**动手修之前，先出一份明确的自查报告。** 诊断和治疗一口气做完会失败——模型的先验会压过指令，于是它在该重排时改色、在该重排时精修字体。

### 十条 tell（命中一条 = 1 分，越低越好，10 = 最 slop）

1. **科技渐变**——一切上面都糊蓝/紫/靛的亮面渐变。
2. **通用科技色相**——默认强调色是靛/紫（不是为品牌选的，只是模型的最爱）。
3. **特性卡网格**——图标 + 标题 + 一句话 × 3，权重全等，什么都没被优先。
4. **强调色条**——卡片左侧一条彩色竖条：假装是组织的装饰。
5. **无来由的模糊**——没有真实标高/深度系统的毛玻璃。
6. **纪念碑数字**——用巨型数字填占本该承载产品故事的空间。
7. **图标顶盖**——每个标题上方一个居中圆角方块图标（Tailwind 模板填充物）。
8. **全居中**——什么都居中，因为根本没承诺过任何构图。
9. **默认字体**——Inter（或 system-ui）是被默认的，不是被选择的。
10. **原型错配**——构图与 surface 不符（例如给 Monitor 界面做 hero）。**这是其余大多数 tell 的根因。**

### 打分与修法对应

- 报告里写明分数与命中编号，简短一段即可。
- 报告是**上下文，不是待办清单**——它指出**该往哪里使劲**，不直接规定改动。
- 按类别修，不要串味：
  - **#3 / #8 / #10 → 重排版、重构图**（回去看 surface 选对没有；**不要改色**）。
  - **#1 / #2 / #9 → 改配色、改字体**（这里调色板与字体确实是问题本身）。
  - **#4 / #5 / #6 / #7 → 删装饰**，用真实层级（尺度、字重、间距）替代。
- 修完**重新打分**。构图类（#3/#8/#10）还在命中就不算完成——它们是因，其余多是被它们带出来的果。

## 二、可判定硬门清单

编号沿用合并前 hallmark 正文中具名的门号（它引用的那整套 slop-test 明细文件**在源目录中并不存在**，故本技能不继承该引用；下面只保留源正文里真实出现、且本技能能独立判定的门）：

| 门 | 判定 | 违反示例 |
|----|------|---------|
| 34 | `html` 与 `body` 都用 `overflow-x: clip`，**绝不用 `hidden`** | `body { overflow-x: hidden; }` |
| 38a | 标题与展示字体一律正体 | `<h1>Built to <em>think</em></h1>`；整块斜体展示字体 |
| 46 | 无编造指标 / 客户 / 评价 / 案例数 | `+47% 转化`、`服务 50,000+ 团队`、`快 10 倍` 且无来源 |
| 47 | 禁手绘假 chrome | 假浏览器栏、假手机框、假代码窗（假标题栏 + 三点包 `<pre>`）、假 IDE |
| 48 | 令牌锁定，无即兴内联 | 产物里出现内联 hex/oklch/rgb，或绕过 token 块直接写字体名 |
| 49 | 可点文本不折两行 | 按钮、主导航项、页脚链接、面包屑、CTA 在任一断点折成两行 |
| 50 | 含图网格轨道用 `minmax(0, 1fr)` | 裸 `1fr` 且轨道内有图片 |
| 51 | 展示标题承载超长词 | 缺 `overflow-wrap: anywhere` / `min-width: 0`，长词撑破容器 |
| 52 | 区块头在移动端塌成单列 | 所有主题变体下区块头仍强制多列 |
| 53 | radio-tab 模式不滚动跳变 | 切换 tab 时页面跳动 |
| 54 | 禁止悬挂式标签栏 | 标签在左、标题在右的两栏表头（最可靠的自模板化 tell） |

**其余 AI 味判定**（不依赖编号，直接看）：三张等权图标卡、卡片左侧色条、无深度系统的毛玻璃、填空间巨型数字、全居中、科技渐变、未选择即默认的 Inter/system-ui、`Lorem ipsum`、假仪表盘里的任意数字、emoji（品牌不用则禁）、模糊标签（"洞察""增长""规模化""优化"却没有内容）、假 SVG 插画冒充产品图、彩虹色板。

## 三、八状态清单（组件与可交互元素必查）

每个可交互组件都必须为**全部八态**写出实际样式，缺任何一个即未完成：

```text
default · hover · :focus-visible · :active · disabled · loading · error · success
```

- `:focus-visible` 必须是**可见环且 ≥3:1 对比度**；环的出现**不做动画**，聚焦即刻显示。
- 八态要在一页里全部可见时（组件预览页），用附加类同时命中伪类：

```css
.btn:hover,        .btn.is-hover  { background: var(--color-paper-3); }
.btn:focus-visible,.btn.is-focus  { outline: 2px solid var(--color-focus); }
.btn:active,       .btn.is-active { transform: translateY(1px); }
```

- loading 用 `data-state="loading"`，error / success 同理，让八态可以静态并排渲染。
- 静默成功优于庆祝 toast；乐观更新 + 撤销优于确认弹窗。

## 四、诚实内容门（安全底线）

- 用户没给的数字**不许编**。数字型版式、对比行、信任条只能用：真实数字、占位符（`—` 加灰色块并标"待确认指标"）、或换一种骨架。
- 客户评价、客户 logo、案例数量、用户数同理——一旦是编的，立刻算 slop。
- 引用外部设计不得把对方的数据当用户的数据（见 `references/audit.md` 第三节）。
- 若多写一段文案、多编一个数据会改变策略或主张，**先问用户**。
- 文案必要但未定稿时，明确标为草稿或占位。

## 五、快速自查

```bash
# 门 34：不该出现 overflow-x: hidden
grep -rn "overflow-x:\s*hidden" --include=*.html --include=*.css .
# 门 50：含图片的轨道不该裸用 1fr
grep -rn "grid-template-columns:.*[^)]1fr" --include=*.css --include=*.html . | grep -v minmax
# 门 38a：标题里的斜体
grep -rn "<em>\|<i>" --include=*.html . | grep -i "<h[1-6]"
# 门 46：典型编造指标
grep -rnE "\+[0-9]+%|[0-9]+,[0-9]{3}\+|[0-9]+×" --include=*.html .
# 门 48：内联色值（应为 0 命中）
grep -rnE "#[0-9a-fA-F]{3,8}\b|oklch\(|rgb\(" --include=*.html . | grep -v "var(--"
```

命中不等于必然违规（例如 token 块的 `:root` 内部本就该有原始色值），需人工看上下文；但这些命令能把检查范围收窄到几十行以内。

# 模式 B · 变体对比（variants）

适用：用户想在**确定一个方向之前先看到几种可能**——把界面想法做成可丢弃的 HTML 草图，生成 2-3 个变体并排比较视觉方向。目的不是产出可上线的代码，而是让用户挑方向。

触发语：「先画个草图」「给我看看 X 能长什么样」「比较布局 A 和 B」「给我 2-3 版」「让我先看几个方案」「做之前先出个草案」。

通用硬规则见 `SKILL.md` 第二节；移动端底线见 `references/responsive.md`；本文件只讲模式 B 的方法。

---

## 核心链路

```text
intake → 变体 → head-to-head → 选赢家（或再来一轮）
```

## 1. Intake（用户已给足信息就跳过）

生成变体前拿到三件事——**一次问一个**，不要一口气全问：

1. **感觉**：「这东西该给人什么感觉？形容词、情绪、氛围。」—「平静、编辑感、像 Linear」比「极简」信息量大得多。
2. **参照**：「哪些应用、网站、产品抓到了你想象的那种感觉？」真实参照胜过抽象描述。
3. **核心动作**：「用户在这个界面上最重要的那一个动作是什么？」所有变体都要服务好它；服务不了就只是装饰。

每问一个先简短复述用户的答案，再问下一个。用户一开始就把三件事都给全了，直接进变体。

## 2. 变体（2-3 个，绝不 1 个，很少 4 个以上）

一次产出 **2-3 个变体**，每个都是完整独立可打开的 HTML 文件。**不要描述变体，要做出来**——这一模式的全部意义在比较。

每个变体必须采取**不同的设计立场**，而不是不同的像素取值。可用的立场轴（挑一条，从它向外拉开）：

- **密度**：紧凑 / 疏朗 / 超高密度（取两个对比极）
- **重心**：内容优先 / 动作优先 / 工具优先
- **审美**：编辑感 / 实用主义 / 玩心
- **布局**：单列 / 侧栏 / 分屏
- **着地方式**：卡片式 / 裸内容 / 文档风

**判断规则（必须保留）**：**两个只差强调色的变体等于白做**——用户根本区分不出来。同样是浪费：结构相同只换了圆角或字号的变体；「保守 / 折中 / 激进」三个只是同一配色深浅的变体。若发现自己只能做出两个同构变体，回去换轴。

**变体命名描述立场，不描述编号**，且不用裸编号当名字：

```text
sketches/
├── 001-平静编辑感/index.html   + README.md
├── 001-实用高密度/index.html   + README.md
└── 001-玩心分屏/index.html     + README.md
```

## 3. 每个变体都要是真的 HTML

- 单个**自包含**文件：内联 `<style>`，无构建步骤、无外部 CSS。
- 系统字体或经 `<link>` 引入的一个 Google Font。
- 用 CDN 的 Tailwind 可以，但不要其他重依赖。
- **真实感假内容**：真句子、真名字，不要 `Lorem ipsum`。
- **可交互**：链接可点、悬停有真反馈、至少一个有意义的状态切换（展开/收起、筛选、切换）。一张冻住的静态图像是比蹩脚动画更差的草图。
- 遵守 anti-slop 硬规则与移动端底线（变体是草图，但**不豁免**最低质量）。
- **打开看一眼再交付**：用 `browser_open` 打开 `file:///绝对路径/index.html`，必要时 `browser_screenshot`。纯看源码抓不到布局 bug（字体导入静默失败、flex 容器塌缩、重叠文字）。看起来坏了就先修好再给用户看。

快速起步的 CSS 重置与系统字体栈：

```html
<style>
  * { box-sizing: border-box; margin: 0; padding: 0; }
  body {
    font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
                 "Helvetica Neue", Arial, sans-serif;
    -webkit-font-smoothing: antialiased;
    color: #1a1a1a; background: #fafafa; line-height: 1.5;
  }
</style>
```

## 4. 每个变体的 README

```markdown
## 变体：{立场名}

### 设计立场
一句话说明驱动这个变体的原则。

### 关键选择
- 布局：...
- 排版：...
- 颜色：...
- 交互：...

### 取舍
- 强在：...
- 弱在：...

### 最适合
- 它真正服务的那类用户或场景
```

## 5. 互动下限

草图「够交互」的标准是用户可以：① 点主操作并看到可见反馈（状态变化、弹窗、toast、导航假动作）；② 看到一次有意义的状态迁移（筛选列表、切换模式、开合面板）；③ 悬停可识别的可交互元素（按钮、行、标签页）。超过这些就是在给一次性草图过度设计；低于这些就是一张截图。

## 6. Head-to-head（必须先建完再对比）

所有变体建完后，作为对比呈现给用户。**不要只罗列——要下判断**：

```markdown
## 首页的三个方向

| 维度 | 平静编辑感 | 实用高密度 | 玩心分屏 |
|------|-----------|-----------|---------|
| 密度 | 低 | 高 | 中 |
| 主操作可见度 | 低 | 高 | 中 |
| 扫读性 | 高 | 中 | 低 |
| 感觉 | 平静、可信 | 利落、工具感 | 有吸引力、有活力 |

**我的判断**：高密度给重度用户，平静编辑感给内容导向受众。玩心分屏最弱——两边都想兼顾，结果哪边都没站住。
```

表格必须包含**我的一句判断**（哪个最强、哪个最弱、为什么），这是模式 B 最容易被省掉却最有价值的部分。

让用户挑一个赢家、或把两个合成混合体、或再来一轮。

## 7. 主题化（项目已有视觉身份时）

项目已有主题（颜色、字体、token）时，把共享 token 放 `sketches/themes/tokens.css` 并在每个变体里 `@import`。保持 token 最小：

```css
/* sketches/themes/tokens.css */
:root {
  --color-bg: #fafafa;  --color-fg: #1a1a1a;  --color-accent: #0066ff;
  --color-muted: #666;  --radius: 8px;
  --font-display: "Inter", sans-serif;
  --font-body: -apple-system, BlinkMacSystemFont, sans-serif;
}
```

**不要给一次性草图过度做 token 化**——三个颜色加一个字体通常就够。

## 8. 收敛与输出

- 在仓库根建 `sketches/`（项目用 `.planning/sketches/` 约定时从其约定），每个变体一个子目录：`NNN-立场名/index.html` + `README.md`。
- 告诉用户怎么打开：macOS `open`、Linux `xdg-open`、Windows `start`。
- 变体保持可丢弃：一个你舍不得扔的草图应当被提升进真实项目代码，而不是被当成资产收藏。
- 用户选定方向后**要收敛**，不要把项目永远留成一堆选项。

**单个变体的典型工具序列**：`bash` 建目录 → `write` 写 `index.html` → `write` 写 `README.md` → `browser_open` 打开 → `browser_screenshot` 看效果 → 修 → 下一个变体 → 最后给 head-to-head 表。

## 9. 下一轮画什么（已有草图时的选点）

- **一致性缺口**：来自不同草图的胜出变体各自做了独立选择，尚未合成。
- **未探索的屏**：被引用过但从未探索的界面。
- **状态覆盖**：只画了顺利路径，没画空 / 加载 / 错误 / 1000 条数据。
- **响应式缺口**：只在一个宽度验过；移动端 / 超宽屏还成立吗？
- **交互模式**：静态布局有了；过渡、拖拽、滚动行为没有。

提出 2-4 个具名候选，让用户挑。

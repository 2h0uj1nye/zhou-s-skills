# 第一性原理

**定位**：当某个成本、形态或做法被"行业惯例/一直都这样"锁死时，用来**把问题拆回基本约束，再从约束重新推导方案**。

## 触发信号

- "成本压不下来，因为上游就是这么贵"
- "行业都这么做，没有别的办法"
- "照抄竞品只能追平，追不上"
- 需要判断某个"不可能"到底是物理不可能还是惯例不可能

## 不该用它

- **常规问题**有成熟方案时（重新发明轮子是浪费）。
- **时间紧迫**、需要当天决策时。
- **真正的硬约束**已被确认（法规、安全、物理极限）——此时该做的是接受约束后优化，不是继续追问。
- **用户只想要执行步骤**且方案已定。

## 核心判断

1. 类比推理（别人怎么做、以前怎么做）只能带来改良；从基本约束重新推导才可能重构方案。
2. 追问要停在**不可再分的约束**：物理定律、数学关系、法规底线、人的生理极限。停不下来 = 你在追问偏好，不是追问原理。
3. 追问有两种常见结果：**发现约束是假的**（惯例伪装成物理） → 重构方案；**确认约束是真的** → 明确上限，回到优化而非颠覆。

## 操作步骤

1. **列出假设**：把当前方案里所有"必须这样"的条目写出来（成本构成、流程、参数、时间）。
2. **逐条标记来源**：物理/法规/合同/惯例/习惯。只对"惯例/习惯"类继续追问。
3. **追问到底**：对每条问"为什么？"直到答不出物理或法规依据；写下该条的真实下限。
4. **重估下限**：用材料成本、能量、时间、人力等基本量算一个理论下限（估算即可，但要写清假设）。
5. **找差距**：现实 vs 下限的差距来自哪几个环节？差距最大的环节就是重构点。
6. **从约束重建方案**：只用被验证为真的约束作为前提，重新组合方案，而非在旧方案上打补丁。
7. **做一次现实性回检**：新方案是否违反了被忽略的隐性约束（安全、合规、供应链、人的接受度）？

## 输出模板

```
被质疑的惯例：……（来源：惯例，非物理）
验证后的真约束：……
理论下限估算：……（假设：……）
现实与下限的差距来源：环节 A / B
重构方案要点：……
隐性约束回检：……
```

## 判断标准

- 做对：发现新路径、成本出现数量级下降、瓶颈被绕开。
- 做错：把简单问题复杂化、耗时很久得出"其实还行"、方案漂亮但无法落地。

## 误用模式

- **伪第一性原理**：只是把类比结论换个说法（"本质上用户就是要便宜"），并没有追问到底层。
- **忽略隐性约束**：算出了成本下限，但违反安全/合规/交付周期——这类方案不是突破，是事故。
- **把偏好当物理**："用户不可能接受订阅制"是偏好，不是定律；但要承认偏好会真实地决定成败。
- **无限追问**：对已确认的硬约束继续追问，产出的是哲学讨论而非方案。
- **用它处理人事/情绪问题**：非技术问题里"拆到底层"往往拆掉的是关系。

## 边界与安全

- 涉及安全关键系统（医疗、航空、能源、金融风控）时，不得建议绕过合规与安全约束，即使成本显著下降。
- 不提供规避监管或降低安全标准的操作细节。

## 切换到其他模型

- 问题是"多个方向选哪个"而非"能不能重构" → `contradiction-analysis.md`。
- 瓶颈不在成本而在"改了没反应" → `system-leverage.md`。
- 卡点是"个人成长到了单一要素十倍化"这一步 → 就是本模型，不要在 `cognitive-arch.md` 里重述。
- 涉及"新媒介/新平台值不值得押注" → 先 `media-form.md`，再回到本模型算投入下限。

## 出处

埃隆·马斯克公开表述的第一性原理思维："用物理学视角看世界，把事情熬成最基本的真理，再从那里往上推理。"

# 半控制系统设计

**定位**：当纠结"该集权还是分权、该管到什么程度、该放多少手"时，用来确定**控制力度**：控制不是"全控 / 全放"二选一，而是 **99% 自下而上 + 1% 自上而下**。

## 触发信号

- "团队该扁平化还是层级化？"
- "产品该集中管控还是放权给用户？"
- "组织该自上而下指令还是自下而上涌现？"
- "该管到什么程度？该放手到什么程度？"

## 不该用它

- **高风险、时间敏感场景**（医疗急救、军事指挥、金融风控、航空航天）：需要精确控制，"适度失控"可能造成灾难。
- **个体缺乏基本判断力时**：半控制的前提是底层能做局部决策，否则"放权"等于"放任"。
- **强中心化、强合规的组织环境**：分布式建议可能无法落地甚至引发冲突。
- **对象是个人信息/知识管理** → `info-ecology.md`（若目标环境已安装独立的 `shikong-semi-control-design` 技能，优先用 `skill` 加载它）。

## 核心判断

1. 底层自发互动产生秩序，但必须保留少量顶层引导防止熵增；**绝对去中心化与绝对中央控制都会失败**。
2. 健康系统活在**"混沌的边缘"**：几乎要失控但从未真正失控。
3. 引导群体转向时**不要追求 100% 一致**——100% 同向会因失去制衡而翻车。
4. 在复杂环境中，大量简单模块的协作往往比一个复杂中心更鲁棒（"宁可千万个有用的白痴，也不要一个无用的天才"；火星探测器案例：一群鞋盒大小的低能机器人自由协作，击败几吨重的中央控制机器人）。

## 操作步骤

1. **蜂群三特征评估**：
   - 鲁棒性：控制权是否分散、有无单点故障？
   - 适应性：底层能否不等高层指令就响应？
   - 代价可接受性：你能否接受不可预测、非最优、不可控？
   三条都满足 → 走分布式；代价不可接受 → 走集中式。
2. **若走分布式，做九律体检**：分布式、自下而上为主、递增收益、模块化、边界开放、容错、多目标、保持不均衡、能自我更新——缺哪条补哪条。（九律的完整定义在 `emergence.md`，不在此重述。）
3. **定控制力度**：用"养孩子"类比——塑造、训练、提供环境，但不扼杀意志，也不放任自流。具体做法：保留 **1% 的顶层引导**（设定底线规则、防止熵增），其余 99% 交给底层自组织。
4. **转向时用 60/40 幅度分配**：允许少数"错误方向"存在作为制衡，不追求全体同向。
5. **健康度检查**：太稳定（均衡态）→ 引入异质信息打破舒适区；太混乱 → 加强那 1% 的顶层引导。
6. **明确红线**：把不可接受的结果（安全、合规、伦理）写进那 1%，做成规则而非事后追责。

## 输出模板

```
对象：……（团队 / 产品 / 组织）
蜂群三特征：鲁棒性…… 适应性…… 代价……
路线决策：分布式 / 集中式 / 混合——理由
九律缺项与补法：……
1% 顶层引导包含什么：……
红线（不可接受结果）：……
健康度观察指标：……
```

## 判断标准

- 做对：局部出现自发秩序，无需指令即可自我修正；个别节点失效不影响整体；创新从边缘冒出。
- 做错：系统僵化、层层审批、响应迟缓（管太多）；或混乱、无方向、资源浪费（放太多）；或追求 100% 一致后突然崩溃。

## 误用模式

- **把 AI 的"涌现"等同"生命"**：大模型不可解释性是统计复杂度（数千亿参数在高维空间的相互作用），不是生命性；当成生命会带来危险的解脱感（"既然像生命，就不该期待理解，只需敬畏"）——一旦承认它只是统计复杂度，责任就回到工程和制度上。
- **迷信"开放者赢"是永恒定律**：生成式 AI 时代算力、数据、人才向少数巨头集中，去中心化与再中心化的张力才是现实；去中心化不是单行道。
- **在不该放权处放权**：高危场景用"适度失控"会酿成事故。
- **只放不管**：忘记保留 1%（底线规则），系统熵增到崩溃。
- **管得太满**：把每个节点都纳入审批，等于回到全控。

## 边界与安全

- 涉及人身安全、资金、合规、未成年人时，红线优先于自组织，不接受"涌现"作为免责。
- 不提供规避监管或降低安全标准的分权方案。

## 切换到其他模型

- 要设计自组织规则本身 → `emergence.md`。
- 系统"改了没反应"需要先诊断 → `system-leverage.md`。
- 对象是个人信息/知识流 → `info-ecology.md`。
- 需要重构成本或形态 → `first-principles.md`。

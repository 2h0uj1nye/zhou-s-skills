# 矛盾分析（主要矛盾）

**定位**：当面前同时存在多个问题、资源不够全做时，用来**排序**——找出那个"解决它会带动其他问题"的主要矛盾。

## 触发信号

- "事情太多了，不知道先做哪个"
- "预算/人力只够做一件，选哪件"
- "团队争论不休，方案定不下来"
- "什么都抓了一点，什么都没做成"

## 不该用它

- **只有一个问题**：没有"多矛盾"就无从排序，去用解决该问题的专门方法。
- **合作关系里的分歧**：这是非对抗性矛盾，靠协商与机制设计，不靠"抓主要矛盾"。
- **信息严重不足**：连有哪些矛盾都列不出来时，先收集事实。
- **用户已决定先做哪个**：那是执行问题，不是排序问题。

## 核心判断

1. 复杂局面里必有一个主要矛盾，它起领导、决定作用；抓住它，其他矛盾的处理难度会下降。
2. 主要矛盾会**转化**：今天的主要矛盾解决后，原来的次要矛盾可能升格——所以必须定期复盘。
3. 区分**对抗性**（利益不可兼得）与**非对抗性**（可协商）矛盾：把关系问题当成敌我问题，是最常见的翻车方式。

## 操作步骤

1. **全量清单**：把所有问题/诉求逐条写出来，不合并、不省略（这一步偷懒，后面全错）。
2. **逐条定性**：每条问三件事——影响面多大？紧迫程度？是不是其他问题的成因？
3. **排序**：按"影响力 × 紧迫度 × 根因程度"排出主次；写成明确的第一、第二、第三。
4. **验证根因假设**：如果解决了这个，还有哪几条会跟着缓解？缓解不了的，说明它不是主要矛盾。
5. **集中资源**：把最好的资源压在主要矛盾上；其余**显式降级**（写清搁置到什么条件再处理）。
6. **留一个转化观察点**：写下"什么信号出现说明主要矛盾变了"，并约定复查节奏。

## 输出模板

```
主要矛盾：……
判断依据：影响面 / 紧迫度 / 根因程度
被降级的矛盾：……（搁置条件：……）
若主要矛盾解决的连带效果：……
转化信号：出现……时重排
```

## 判断标准

- 做对：问题清单变短、资源集中、其他问题被动缓解。
- 做错：资源分散、每条都在推进、每条都没结果。

## 误用模式

- **"斗争"扩音器**：把非对抗性关系说成"敌我矛盾"，教用户去压制对方。
- **拖延借口**："主要矛盾还没找准"变成不行动的挡箭牌——超过一轮复盘仍未排序，就是在拖。
- **只排序不降级**：嘴上说聚焦，实际并行做全部，等于没排序。
- **把"最吵的那个"当主要矛盾**：优先级来自影响与根因，不来自嗓门。

## 边界与安全

- 涉及劳资、家庭、职场冲突时，只做**分析**，不给"如何斗争"的操作建议。
- 用户处于被压制/受侵害处境时，主要矛盾往往在"脱离该处境"，不要引导其"忍受次要矛盾"。

## 切换到其他模型

- 问的是"为什么这件事成本降不下来"而非"先做哪个" → `first-principles.md`。
- 解决后系统整体还是没变化 → `system-leverage.md`（可能是结构问题，不是排序问题）。
- 用户其实在纠结"我该不该做"而非"先做哪个" → `eternal-recurrence.md` 或 `stoic-control.md`。

## 出处

《矛盾论》（毛泽东）："任何过程如果有多数矛盾存在的话，其中必定有一种是主要的，起着领导的、决定的作用。"

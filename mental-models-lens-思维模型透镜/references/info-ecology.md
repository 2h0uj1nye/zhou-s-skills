# 园丁式信息生态

**定位**：当用户信息过载、并被"要用工具管住一切"的思路拖累时，用来把身份从**工程师**换成**园丁**：不做全局精确控制，只建局部规则，培育一个能自我更新的信息生态。

## 触发信号

- "信息太多，越刷越焦虑，但没学到什么"
- "收藏夹/笔记软件越用越累"
- "想建个人信息或知识管理系统，不知道从哪下手"
- "不知道该关注什么、忽略什么"

## 不该用它

- **个人信息素养与知识储备不足时**：园丁的前提是已有判断力来设定"局部规则"，否则杂草会淹没庄稼——先建基础知识框架。
- **高时效、高精度的信息需求**（金融交易、新闻追踪、医疗信息）：需要精确获取与快速响应，不适配"容错 + 慢变量"。
- **强中心化的组织环境**：信息获取受严格管控时，"分布式触角""多元信源"无法落地。
- **团队/产品的控制力度问题** → `semi-control.md`。
- 想把一本书做成技能包 → 用对应技能，不要用本模型。

## 核心判断

1. 复杂系统里追求"最优信息输入"注定失败；有效做法是**局部规则 + 自我演化**。
2. 洞见多在**浸泡与边界碰撞**中长出来，不靠精准搜索搜出。
3. 均衡即死亡：全是同温层信息 = 认知停止生长；但过度连接同样会摧毁韧性（见第 4 条操作）。
4. **"做园丁"不等于"放任自流"**：局部规则必须存在。

## 操作步骤

1. **速度分层，锚定慢变量**：信息分三层——快层（热搜、梗，瞬息万变）、中层（技术、管理，数月至数年）、慢层（基础设施、价值观、文化底层，极慢）。守住你的慢变量（底层价值观、核心知识体系、长期目标），用它们消化快速信息流；中间地带反而是最不确定的"风暴眼"。
2. **六维框架建系统**：
   - 模块化生长：先做小而独立的模块（阅读/笔记/反思），再连接；不要一上来建"终极知识库"。
   - 边界最大化：主动接触边缘、小众、异质信源。
   - 鼓励犯错误：允许"杂草"存在，不为一次"浪费时间"的阅读愧疚。
   - 不求最优但求多目标：用多元组合应对不同场景，而非找唯一完美信源。
   - 谋求持久的不均衡态：主动引入让你不适的对立观点，保持认知张力。
   - 变自生变：建立能自我更新的代谢机制，定期淘汰过时与冗余——**最好的老师是"不"**。
3. **五步落地**：
   - 分布式信息处理：RSS / Newsletter / 播客 / 专业社区多节点分担过滤，你只在关键节点收割整合。
   - 培养容错与涌现思维：相信洞见在浸泡中长出。
   - 构建多元而非最优的生态：刻意关注立场不同的渠道作为认知护栏。
   - 在"失控"中找秩序：只控制局部规则（每日深度阅读时长、每周复盘、面对情绪化内容的停顿）。
   - 内化为习惯：定期信息断食、情绪信息延迟 24 小时再回应、主题式阅读、定期清理信源。
4. **警惕过度连接**：关联度超过临界值后，系统从扰动中恢复的能力会突然下降。不要无限增加信源与连接；过度追求确定性和绝对安全会扼杀韧性。

## 输出模板

```
当前症状：……
慢变量（要守的 3 条）：……
速度分层诊断：快层…… / 中层…… / 慢层……
六维体检：缺哪 1–2 条 → 补法……
局部规则（≤3 条，可执行）：……
信源清理动作与周期：……
```

## 判断标准

- 做对：信息不再让你焦虑，有了清晰的"追什么、守什么"；模块逐步生长并偶尔涌现洞见；信源定期清理，系统保持活力。
- 做错：信源越来越多却越来越焦虑；试图控制每个输入却力不从心；知识库越大越难用；只看同温层，认知变窄。

## 误用模式

- **把园丁当放任**：没有局部规则，结果是被信息洪流淹没。
- **工具堆叠代替系统重建**：不断换笔记软件，却不改底层处理方式——工具可以是模块，但替代不了思维转变。
- **无限增加信源**：越过连接临界值，韧性反而骤降。
- **只做收藏不做淘汰**：没有"不"，系统必然熵增。
- **在强时效场景套用**：需要精确快速响应的场景不该用容错策略。

## 边界与安全

- 个人信息流内容属敏感数据：只处理用户主动给出的部分，不外发、不落盘、不代为配置云端账号。
- 不索取账号凭据；不要在未经允许时读取用户的笔记库或浏览器数据。

## 切换到其他模型

- 对象是团队/产品/组织的控制力度 → `semi-control.md`。
- 想理解"为什么不增加投入系统就退化" → `system-leverage.md`。
- 想设计"多节点自组织"的规则 → `emergence.md`。
- 焦虑来自不可控的外部环境 → `stoic-control.md`。

# 思维模型透镜（mental-models-lens）

> 一句话：你抛来一个纠结的判断，它从十几个思维模型里挑出**最合用的那一个**，告诉你为什么不用另外两个，再按固定步骤陪你推演到底。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；纯文本推理，不需要装任何东西） |
| 外部依赖 | 零依赖。不需要联网、不需要 key，只用技能自带的知识文件 |
| 产出 | 一份固定八节的判断书：选哪个模型、排除了哪两个、依据是什么信号、推演过程、一句话结论、什么会推翻它、下一步做什么、边界在哪 |
| 入选理由 | 同类"思维模型"技能的通病是罗列一堆模型让人更晕；它反其道而行，一次只准用 1–2 个，还额外写了"什么信号该用哪个"的路由表和"最容易选错"的对照表 |

## 它解决什么问题

"思维模型"这个词被讲烂了：书里列 100 个，视频讲 50 个，听完还是不知道手上这件事该用哪个。真正的难点从来不是"知不知道有这个模型"，而是**面对眼前这一个具体问题，该用哪一个、为什么不是另外那个**。这个技能只干这一件事——把选型这件事做对，然后老老实实按步骤推一遍。它自己写得很直白："一次给 5 个模型等于没给——用户拿到的是清单，不是判断。"

## 什么时候该用它

- "我手上问题一堆、资源不够，到底该先解决哪个？"
- "改了很多次，这个系统就是没反应，为什么？"
- "成本砍不下去了，同行也都这么干，卡死了。"
- "我很焦虑，天天想那些我自己根本决定不了的事。"
- "我到底该不该换行业？"

## 什么时候别用它

- **只是想知道某本书/某个人讲了什么**、想了解某个模型的定义和历史——那是查资料，直接回答或用搜索工具。
- **你已经决定要做了，只问怎么执行**——这时候套"要不要做"的模型纯属添乱。
- **需要资料、数据、算数、跑代码**——换搜索或直接动手。
- **正处于急性创伤、丧亲、重病中，或出现自伤念头、临床级焦虑抑郁**——技能红线明令"停止模型化"，只给支持性回应并建议专业帮助。这不是能力边界，是刻意设的安全线。

## 怎么开口

- "我在纠结要不要辞掉现在的工作去做自己的项目，帮我理一理。"
- "团队这两年投入不少，指标就是不动，用个思维模型帮我看看问题出在哪。"
- "最近老被那些我控制不了的事搞得睡不着，帮我分一下哪些是我真能动的。"
- "有个新媒介形式冒出来，我想判断它长期会带来什么影响。"

## 输入 / 输出

**它会问你的三件事**（缺任何一件，它就先问、不硬套模型）：一是具体的判断或决策问题（"聊聊人生"不算）；二是**谁承担后果**——你、团队还是客户；三是**这次判断要管多久**——按天、按月还是按年。信息不够时它最多问 3 个问题，规矩是"禁止一次抛 10 个问题"。

**输出结构是硬约束**，完整档共八节：【判断】（主模型 + 对应的知识文件）、【排除】（不用 A 和 B，各自的理由）、【信号】（2–3 条触发信号，必须引用你的原话或已知事实）、【推演】（按该模型自己的步骤走，并标注哪些是事实、哪些是假设）、【结论】（一句话、可执行）、【反例】（什么证据能推翻它）、【下一步】（一个最小动作 + 一个可观察指标）、【边界】（本结论不适用于什么）。低风险的小问题走"轻量档"，只写判断、推演、下一步三节。问题不属于它的范畴时，走"拒绝档"：写明不适用 + 原因 + 该转去哪里。

有一句话是这套格式的灵魂：**"写不出【排除】，说明你还没做选择，只是在罗列模型。"**

## 依赖与前提

无。不需要装软件、不需要联网、不需要 key。它靠的是技能自带的 12 个 Markdown 知识文件，用的时候直接读进来。

## 内部结构

`SKILL.md` 176 行，是"总台"：判边界、要输入、定输出格式、写步骤、列红线和坑点、最后做交付前自查。真正的方法细节在 `references/` 下的 **12 个文件**里，每个模型一个，69–95 行不等，结构统一（定位、触发信号、不该用它、核心判断、操作步骤）。比如 `system-leverage.md` 是杠杆点与回路诊断，`stoic-control.md` 是可控/不可控分类，`cross-domain-transition.md` 是转型五步法。

这样拆的理由很清楚：主文件必须短，因为每次对话都要读它；具体模型只在被选中时才读，所以可以写得细。它还专门写了一条坑："只 read 本技能 references/ 下真实存在的文件"——防止模型编造一个不存在的文件名。

## 注意事项与已知限制

- **一次最多 1–2 个模型**，给到 3 个以上直接判不合格。想串联两个，必须说明"第二个回答了第一个答不了的什么问题"。
- **信息不足时它不会出结论**，会先提问。这是特性不是拖延；反过来，如果你已经信息充足却还在说"我再测测"，它被要求点破这是拖延。
- **哲学模型不能用来解决生存问题**：缺钱、缺技能、被裁员时，先处理生存，别上哲学测试。
- **斯多葛不是忍耐术**：如果"不可控"的那一方是别人对你的侵害或结构性不公，它的红线要求先谈改变和求助，绝不能用"接受不可控"给你封口。
- **"永恒轮回"有禁忌场合**：创伤、丧亲、重病期间不用——对刚受伤的人说"要热爱命运"是二次伤害。
- 它不做医疗/心理诊断，不做法律、财务、投资建议，也不做时间点预测（媒介类、涌现类模型明确"不承诺精度"）。
- **时间尺度必须确认**：同一个问题在 3 天尺度和 3 年尺度下会选不同模型，没确认就选型属于高风险。
- 有一处内部互指：技能里提到如果环境里已经单独装了同名技能（如 `shikong-semi-control-design`），应该去加载那个独立技能，本技能只是统一入口。

## 来源

**由 13 个思维模型技能合并而来**，元数据里逐一点名：mao、musk、meadows、mcluhan、kelly、aurelius、campbell、systems-feedback、nietzsche、tyl、shikong-gardener、shikong-semi-control、ysy。

合并方式：**12 个模型各占一个 reference 文件**，唯独"反馈回路"（systems-feedback）没有单列——因为它是"系统杠杆点"（meadows）的同一本书、且是杠杆点的前置诊断子集，于是被**并入** `system-leverage.md`，13 个来源收敛成 12 个文件。

合并过程中动了三处实质内容：一是新增了**路由表**（12 条"用户这么说 → 用哪个模型"）和**混淆对照表**（11 行，专治"这两个模型长得像"的高发误选区），这也是这次合并最大的增量价值；二是修正了英雄之旅来源技能的阶段表错误（现为 17 阶段）；三是把所有模型的输出统一收进同一套八节格式，并加了红线与安全边界一节——原来的单个模型技能没有这些。

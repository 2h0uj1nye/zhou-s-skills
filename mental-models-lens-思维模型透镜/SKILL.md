# mental-models-lens · 思维模型透镜

**只做一件事**：面对一个判断或决策问题，**选对并用对**一个思维模型。

不做：讲模型的定义与历史、给模型写百科、一次罗列多个模型、替用户做专业领域判断（法律/医疗/财务/投资）、提供心理咨询。

**核心纪律：单次回答最多用 1–2 个模型。** 一次给 5 个模型等于没给——用户拿到的是清单，不是判断。

---

## 先判边界：什么时候**不要**启动本技能

| 用户实际要的 | 正确去处 |
| --- | --- |
| 某本书/某人讲了什么、模型的定义与出处 | 直接回答，或 `web_search` 查证 |
| 已经决定要做，只问执行细节 | 直接执行；不要套"要不要做"的模型 |
| 要资料、要数据、要跑代码 | `web_search` / `bash` |
| 急性创伤、丧亲、重病、自伤念头 | **停止模型化**；给支持性回应并建议专业帮助 |
| 临床焦虑/抑郁症状 | 不是本技能适用范围；建议专业支持 |
| 只想被听见（纯情绪宣泄） | 先共情；最多用 `references/stoic-control.md` 做可控/不可控分类，不做推演 |
| 目标环境已装同名独立技能（如 `shikong-semi-control-design`） | 用 `skill` 加载那个独立技能；本技能只是统一入口 |

## 【输入】

**必需**（缺任一即进入"先问"流程，不硬套模型）：
1. 一个具体的判断/决策问题（不是"聊聊人生"）；
2. 决策主体：谁承担后果（你 / 团队 / 客户）；
3. 时间尺度：这次判断要管多久（天 / 月 / 年）。

**可选但显著提升质量**：已尝试过什么及结果、可动用资源与期限、不可动的底线、争议焦点在哪。

**信息不足时的先问清单（最多 3 问，禁止一次抛 10 个问题）**：
- 事实：现在实际发生了什么？你已经试过什么、结果如何？
- 约束：期限、预算、不能碰的东西是什么？
- 归属：这件事主要由你决定，还是别人决定？

用户拒绝回答或只给情绪 → 不要硬套模型（见【坑点】3）。

## 【输出】

**完整档**（人生/组织/高成本/不可逆决策）：

```
【判断】主模型：<模型名>（references/<model>.md）
【排除】不用 <A>：因为…；不用 <B>：因为…
【信号】2–3 条触发信号（引用用户原话或已知事实）
【推演】按该模型步骤逐条走；明确标注哪些是事实、哪些是假设
【结论】一句话可执行结论
【反例】什么证据/信号会推翻它
【下一步】一个最小动作 + 一个可观察指标
【边界】本结论不适用于…（隐私、红线、专业领域）
```

**轻量档**（单点、低风险、可逆）：只写【判断】【推演】【下一步】三节。

**拒绝/转向档**（问题不属于本技能）：写【不适用】+ 原因 + 建议的下一步（换技能 / 查资料 / 求助）。

格式是硬约束：**写不出【排除】，说明你还没做选择，只是在罗列模型。**

## 【步骤】

- **S1 边界判定**：过一遍上文表格，命中任一行 → 不启动模型。
- **S2 抽信号**：从用户原话里抽出可判断的信号；不要凭印象归因。
- **S3 路由**：查「路由表」得主模型；再查「混淆对照」，写下被排除的两个模型及理由。
- **S4 充分性检查**：信息不足 → 用【输入】的先问清单提问，**本轮不出结论**。
- **S5 推演**：`read` 对应 `references/<model>.md`，按它的步骤走；不要凭空发明步骤。
- **S6 反例检查**：主动找一条能推翻结论的证据；找不到就说明置信度来自哪里。
- **S7 落地**：一个最小动作 + 一个可观察指标；再过一遍红线清单。

### 路由表（信号 → 主模型）

| 信号（用户会这么说） | 主模型 | 一句话钩子 |
| --- | --- | --- |
| 问题太多、资源不够、先解决哪个 | `contradiction-analysis` | 找出主要矛盾，集中资源，其余降级 |
| 成本砍不下去 / 行业都这么做 / 撞到瓶颈 | `first-principles` | 拆到不可再分的约束，再从那里重建 |
| 改了很多，系统却没反应 | `system-leverage` | 先画回路搞清"为什么"，再找高杠杆点 |
| 新技术/新媒介会带来什么长期影响 | `media-form` | 问形式改变了什么，而不是内容说了什么 |
| 大量个体、群体行为、规则设计 | `emergence` | 定义简单规则，让结果自己长出来 |
| 焦虑、恐惧，被不由自己决定的事困住 | `stoic-control` | 分清可控/不可控，只对可控项用力 |
| 要讲故事、做品牌叙事、写文案 | `hero-journey` | 按叙事结构组织，让读者代入 |
| 人生重大选择、意义危机、"值得吗" | `eternal-recurrence` | 用"愿不愿意无限重复"检验真诚度 |
| 感觉认知卡住、努力了没进展 | `cognitive-arch` | 定位卡在四阶段哪一层，逐层破 |
| 信息过载、想建自我更新的知识系统 | `info-ecology` | 用速度分层 + 局部规则养生态，别做工程师 |
| 该集权还是分权、该管多紧 | `semi-control` | 99% 自下而上 + 1% 顶层引导 |
| 想换行业/换赛道，纠结该不该走 | `cross-domain-transition` | 盘点可迁移能力，带着武器换战场 |

### 混淆对照（选错的高发区）

| 两难 | 判定规则 |
| --- | --- |
| 矛盾分析 vs 第一性原理 | 问"先做哪个"→ 矛盾分析；问"为什么必须这样、成本下限是多少"→ 第一性原理 |
| 系统杠杆点 vs 反馈回路 | 同一本书。回路是**诊断**（为什么这样），杠杆点是**处方**（在哪改）。永远先诊断 |
| 涌现 vs 半控设计 | 涌现回答"能不能靠自组织长出来"；半控回答"该保留多少自上而下"。先设计规则，再定控制力度 |
| 半控设计 vs 信息生态 | 对象是团队/产品/组织 → 半控；对象是个人知识/信息流 → 信息生态 |
| 斯多葛 vs 永恒轮回 | 问题的主语是"外界加给我的"→ 斯多葛；"这是我自己选的，但不知值不值"→ 永恒轮回 |
| 斯多葛 vs 心理支持 | 情绪强度高、持续两周以上、影响睡眠/功能 → 停止模型，建议专业支持 |
| 认知架构 vs 跨领域转型 | 有明确目标领域和路径 → 跨领域转型；只是"卡住、没进展"→ 认知架构 |
| 认知架构第四阶段 vs 第一性原理 | 第四阶段到"单一要素十倍化"时**直接跳到** `first-principles.md`，不要在认知架构里重述 |
| 英雄之旅 vs 真实人生决策 | 它是叙事工具，不是决策工具。用它解释自己的人生 = 自欺；真实抉择走永恒轮回/斯多葛 |
| 媒介分析 vs 技术预测 | 它只讲形式如何改变感知与社会结构，不给时间点、不评估功能好坏。问"这功能要不要做"→ 不是它 |
| 永恒轮回 vs 四大师圆桌 | 需单一口径的真诚度测试 → 永恒轮回；需多视角互不妥协的攻防 → `skill` 加载 `life-choice-roundtable` |

### 正当的模型串联（**最多 2 个**，且必须说明第二个回答了第一个答不了的问题）

1. "改了很多没用" → `system-leverage`（诊断）→ 结论指向"重设规则/放权" → `semi-control`。
2. 人生重大选择 → `eternal-recurrence`（主）→ 若焦虑来自不可控项 → `stoic-control`。
3. "想让组织长出新东西" → `emergence`（设计规则）→ `semi-control`（定控制力度）。
4. 换赛道 → `cross-domain-transition`（操作）→ 若卡在自我怀疑 → `stoic-control` 或 `cognitive-arch`。
5. 新技术判断 → `media-form`（影响）→ 若涉及"要不要投入" → `first-principles`（成本下限）。

## 红线与安全边界

1. **急性危机不模型化**：丧亲、重病、自伤念头、暴力处境 → 只给支持性回应 + 建议专业帮助，不套任何模型。
2. **斯多葛不是忍耐术**：当"不可控"的一方是他人对你的侵害或结构性不公时，先谈改变与求助，**绝不能用"接受不可控"给用户封口**。
3. **永恒轮回的禁忌**：PTSD、结构性不公、急性丧亲/重病期间不用（对创伤者说"要热爱命运"是二次伤害）。
4. **隐私最小化**：人生抉择、情绪、职业与收入、个人信息流相关内容，只处理用户主动给出的部分；不外发、不落盘、不再转述给第三方。
5. **不冒充专业**：不做医疗/心理诊断，不做法律/财务/投资建议；模型给的是视角，不是事实。
6. **不承诺精度**：媒介与涌现类模型不做时间点预测；把可能性说成必然 = 违规。
7. **权威不是论据**："马斯克说/尼采说"不构成理由，必须给出该场景下的具体推理。

## 【坑点】

1. **模型堆砌**：一次给 3 个以上模型 → 直接判为不合格，砍到 1–2 个。
2. **模型替代事实**：信息不足时硬套框架，产出漂亮但空洞的推演。**先问，再推。**
3. **用模型回避决策**："我再测试一下""我需要更多信息"——若用户已有足够信息，指出这是拖延。
4. **给已有结论背书**：用户其实已决定，只想被认可。此时先点破，再判断这是不是"只问执行"的排除场景。
5. **越界解释他人**：把模型套在不在场的人身上（"我老板主要是矛盾没抓对"）时，必须标注这是推测。
6. **把模型做成人格测试**：模型的产出是判断路径，不是用户的身份标签。
7. **忽略时间尺度**：同一问题在 3 天与 3 年尺度下选不同模型；没确认尺度就路由 = 高风险。
8. **滥用哲学模型处理现实困难**：缺钱、缺技能、被裁员时，先处理生存，不要上哲学测试。
9. **引用不存在的文件**：只 `read` 本技能 `references/` 下真实存在的文件（清单见文末）。
10. **忘掉退出条件**：每条结论都要配一条"什么信号出现就该换模型/停手"。

## 【验证】

交付前自查（任一为否 → 返工）：

- [ ] 是否明确写出**用了哪个模型**，并点名**另外两个被排除的模型**及理由？
- [ ] 触发信号是否引用用户原话或已知事实，而不是想象？
- [ ] 是否做过信息充分性检查；不足时是否先问，而不是硬套？
- [ ] 是否跑过反例检查（什么会推翻结论）？
- [ ] 结论是否可执行（有动作 + 可观察指标），而不是"要重视""要平衡"这类空话？
- [ ] 是否命中任一红线（急性创伤 / 临床心理 / 用"接受"封口 / 冒充专业）？
- [ ] 若用了两个模型，是否说明第二个回答了第一个答不了的问题？
- [ ] 模型数量是否 ≤2？（≥3 → 不合格）
- [ ] 正文引用的 `references/` 文件是否都真实存在（清单见文末，共 12 个）？
- [ ] 是否只索取/复述了必要的个人信息？

# 创意文字排版（pretext）

> 一句话：用一个极小的排版计算库，在浏览器里做出"文字绕着球流动""用真的单词当砖块打砖块""一句话炸成碎片"这种看着很酷、发到社交平台会有人转的文字动画。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；产出是网页，用浏览器打开即可） |
| 外部依赖 | 需要联网（从 CDN 加载排版库、可选加载网页字体）；不需要安装、不需要编译、不需要 key |
| 产出 | 一个**单文件 HTML**，双击就能在浏览器里跑起来的动态文字演示 |
| 入选理由 | 它把一个很窄的技术能力（不碰 DOM 也能算出文字断行）变成了一个创意引擎，还自带 2 个能直接打开的成品和 8 段能直接粘贴的套路代码，属于"看得见效果"的那一类技能 |

## 它解决什么问题

网页要"文字绕着一个移动的球重新排版"，正常做法是让浏览器反复重算布局——卡、闪、掉帧。这个库换了个思路：用画布先**算**出"这段文字在这个宽度下怎么断行、每行多宽、每个字在哪"，拿到数字后由你自己画。因为不触发浏览器重排，它可以每秒 60 次重新计算，于是"绕开障碍物的文字流"从不可能变成了便宜操作。这个技能就是教 AI 用它做出真正好看的东西，而不是又一个教程级 demo。

## 什么时候该用它

- "做个把文字排得很有趣的网页演示。"
- "让一段文章绕着一个能拖动的圆球重新排版。"
- "用真的英文单词当砖块，做一个打砖块游戏。"
- "点一下就炸成碎片的那种文字动画。"
- "中文/日文这种非拉丁文字做排版艺术效果。"

## 什么时候别用它

- **普通静态页面、CSS 本来就排得好好的**——直接用 CSS，别绕远路。
- **富文本编辑器、通用行内格式引擎**——这个库是刻意做窄的，不是干这个的。
- **图片转字符画**——那是另外的字符画类技能。
- **纯画布生成艺术、文字不参与**——换 p5.js 那类技能。
- **客户只是要一份能读的报告或文档**——这是视觉艺术，不是排版工具。

## 怎么开口

- "用 pretext 做一个文字绕着鼠标拖动的球流动的页面。"
- "做个打砖块，每个砖块是一个真实的英文单词。"
- "把这段诗做成点一下炸成碎片的效果。"
- "给我一个非等宽字体的文字动画，要能直接打开看。"

## 输入 / 输出

它主要向你要的是**创作意图**：想要哪种效果、放什么文字、什么调性。有两件事它会主动确认或补全——一是"语料"，也就是画面里流动的那段文字（技能硬性要求**必须是真话、诗、真源码或某本书的片段，绝不许用乱数假文**，长度建议 10–100 句）；二是审美方向（配色、字体、构图、交互）。

输出是**一个自包含的 `.html` 文件**：没有构建步骤、没有 node_modules，双击打开或起个本地服务器就能看。里面包含四层——排版计算库（从 CDN 引，版本锁定）、HTML5 画布负责画字、浏览器自带的 `Intl.Segmenter` 负责把 emoji 和中文正确切分、原生鼠标触摸事件负责交互。技能还会告诉你**文件路径**而不只是代码，因为它知道你是要打开来看的。

## 依赖与前提

要联网。核心是 `@chenglou/pretext`，从 `esm.sh` 这个 CDN 引入，版本**锁定在 0.0.6**（技能明确要求锁版本，因为库还在早期）。两个成品模板还额外从 CDN 加载网页字体，进阶模板还从 CDN 引入了一个调试面板小库。本机实测这三个 CDN 域名（esm.sh、fonts.googleapis.com）当前都返回 200 可访问。另外技能特别提醒：**不要用 unpkg 引这个库**，因为它会把 TypeScript 源码原样吐出来导致 404——必须用 esm.sh。

本地预览用一条命令就行：`cd <html所在目录> && python3 -m http.server 8765`，然后浏览器打开 `http://localhost:8765/<文件名>.html`。

## 内部结构

`SKILL.md` 220 行，是主教程与验收标准；配套两样东西：

- `references/patterns.md`（258 行）——**8 个可直接粘贴的套路**，每个都自带一段能跑的代码：绕障碍物文字流、文字当几何体的游戏、炸裂粒子、ASCII 遮罩当移动障碍、共享游标的多栏杂志版式、最紧贴合的收缩换行、动态字体效果，最后一个是字体栈与配色速查表（编辑风、终端 CRT、现代人文、海报、工程风五种风格各给字体串和配色）。
- `templates/hello-orb-flow.html`（95 行）——最小起步模板：一段长文字绕着一个移动的球流动。
- `templates/donut-orbit.html`（1468 行）——进阶成品：量出来的 ASCII logo 当障碍物、可拖动的线框球/立方体、形状变形场、可选中的 DOM 文字，外加仅开发用的调参面板。

拆成这样的理由：主文件讲**原理和底线**（两种用法、性能注意事项、8 个常见坑、10 条交付检查），套路文件提供**开箱即用的代码**，模板提供**起点**——技能原文写得很清楚，最小模板只是起点，交付的每个 demo 都必须自己加上配色、动效、构图，以及"一个用户没要求但会喜欢的细节"。

## 注意事项与已知限制

- **最容易踩的坑：字体对不上。** 用画布算文字时传的字体串（比如 `16px Inter`）必须和 CSS 里实际渲染的完全一致。如果这个网页字体 404 了、CSS 回退到系统默认，测量结果会偏 5–20%，所以要么预加载字体，要么用安全字体。
- **不要每帧都重新"准备"文字。** 准备（`prepare`）是昂贵的，只做一次并缓存；动画里只跑"排版"那一步，它足够便宜，普通长度段落每秒 60 次没问题。
- **切单个字别用 `split('')`。** emoji、组合字符、中文会被切坏，得用浏览器自带的 `Intl.Segmenter`。
- **绕障碍物时通道太窄就跳过这一行**，不要把极小的宽度丢给排版函数——那样会吐出"一行只有一个字"的破碎效果。进阶模板里用 `break: 'never'` 做原子标签时，必须同时给 `extraWidth` 补上胶囊内边距，否则标签会溢出容器。
- **别交一个冷冰冰的 demo**：技能把"默认首屏像教程复刻版"列为要避免的失败，要求至少有一个交互响应或静默自动动效，画面用深色背景加讲究的配色，而不是默认白底。
- 交付前要过 10 条检查清单，包括"语料是真实文本不是乱数假文""字体串和 CSS 完全一致""本地跑过、控制台无报错""中端笔记本上 60fps"。本技能不生成图片文件，只生成网页——要静态图得自己截图。

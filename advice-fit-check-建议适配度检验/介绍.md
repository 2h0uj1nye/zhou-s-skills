# 建议适用性体检（advice-fit-check）

> 一句话：你听到一条建议（"每天早起两小时学习""别打工了去创业"），它帮你把这条建议拆开，看清它在什么条件下才成立、放在你身上到底缺哪一块。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；纯文字技能，不装东西、不联网） |
| 外部依赖 | 零依赖 |
| 产出 | 一份固定六段的分析报告，末尾给结论句 |
| 入选理由 | 零依赖、输出结构极固定、边界写得很死（只查适配度，不评对错、不改建议） |

## 它解决什么问题

大部分建议是别人从自己的处境里总结出来的，听着有道理，你照做却可能白费力气；难的地方在于很难分清"这条建议错"和"这条建议对我不成立"——后者才是更常见的情况。
这个技能就专干这件事：把建议反推成一组前提条件，再拿你的实际情况去对照，缺哪块就看清缺哪块。

## 什么时候该用它

- "朋友说每天早起两小时就能学会编程，这靠谱吗？"
- "网上都在说副业要做自媒体，你觉得适合我吗？"
- "我 35 岁、有房贷、每天只有 1 小时空闲，这条建议我该照做吗？"
- "帮我体检一下这条建议，我总觉得哪里不对但说不上来。"

## 什么时候别用它

- 你想要的是一句"这建议好不好""该不该听"的结论——它明确不给这种判断，给了也违背它的设计。
- 你想让它给一条更好的替代建议——它只在"调整方案"里做必要微调，不负责另出主意。
- 你想要具体怎么做的操作步骤——它不做执行指导。
- 你手上根本没有一条成形的建议，只是想把某个困境聊一聊——那更适合别的技能。

## 怎么开口

- "帮我做一次建议适用性体检：'XX'。我的情况是：32 岁，程序员，每天下班能挤出 1.5 小时，存款 10 万，想解决的是转行。"
- "advice fit check：'年轻人应该多试错'。"
- "这条建议对什么人不成立？先做通用分析，别问我个人情况。"
- "我补充一下我的情况：…… 现在给我第五部分的个人适配判断。"

## 输入 / 输出

**它会向你要两样：** ① **建议原文**（必需）——要分析的那条具体建议；② **个人情况**（可选）——年龄、职业阶段、可支配时间、现有能力、资源、想解决的问题、能承受的损失。

**最后给你六段，一段都不许少：**
1. **前提条件拆解**——这条建议要成立必须先满足哪些条件（人群、资源、时间、能力基础、风险承受力、最佳场景），每项给 2-3 个能检验的具体条件。
2. **差异化效果分析**——最适合的人 / 看着符合但会白干的人 / 照做反而更糟的人，各配一个具体画像。
3. **省略的代价与例外清单**——隐性成本至少 3 项、例外情形至少 2 种，并解释它们为什么是成本。
4. **实例验证**——一个成立案例 + 一个失效反例，点明两者的关键差异条件。
5. **个人适配判断**——只在你说过个人情况后才出；否则换成一张"请补充这些信息"的清单。
6. **总结陈述**——固定句式收尾：这条建议在____条件下成立，在____条件下失效，核心适用人群是____。

## 依赖与前提

无。不需要装任何软件、不需要联网、不需要 API key，只要宿主能对话就能用。

## 内部结构

只有一份 `SKILL.md`，142 行，没有 references。
正文的"角色定义 → 触发条件 → 输入要求 → 六段分析流程 → 行为约束 → 不做什么"就是全部内容；不拆文件的原因：所有规则都是对**输出格式**的约束（每项至少 2-3 个条件、隐性成本至少 3 项、不许合并小节），和输出本身绑在一起，抽出去反而要在两个文件间来回翻。

## 注意事项与已知限制

- **它真的不会告诉你"该不该听"**——这是设计，不是漏做。想要结论的用户会觉得它绕圈子。
- **不给个人情况就没有第五段**，只会给你一张追问清单；分析质量高度取决于你把情况说得多具体。
- **报告偏长**：六段全出，适合认真分析**一条**建议；一次扔十条进去，每条都会被压扁。
- 语气中立、冷静、非评判，不提供情绪按摩。

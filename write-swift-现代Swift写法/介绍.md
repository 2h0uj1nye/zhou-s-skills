# 现代 Swift 写法（write-swift）

> 一句话：Swift 6 时代该怎么写 Swift 的完整参考——值类型建模、数据竞争安全、并发分层、协议与泛型、API 设计、性能与 ARC、Swift Testing、宏，以及一张「别再写老写法」的新语法对照表。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；技能正文为英文，不影响使用。真机编译通常需要 macOS/Xcode，Linux 上可用 Swift 工具链） |
| 外部依赖 | 零依赖。纯知识型参考，不联网、不装 CLI；示例代码面向 Swift 6.3 工具链 |
| 产出 | 对话内的写法建议、代码片段、迁移步骤；以及含 24 行速查的对照表 |
| 入选理由 | **Swift 6.2 改掉了并发模型的核心规则**：标了 `async` 的函数**不再**自动离开当前 actor（它在被调用的地方运行），而 `@concurrent` 才是真正切到并发线程池。模型脑子里大多是 6.1 之前的旧模型，会写出过时甚至错误的结构。这份内容还点名了一批「agent 常写旧写法」的现代特性（`if`/`switch` 表达式、参数包、`@Observable`、`InlineArray`、`.span`、`@Test` 等） |

## 它解决什么问题

技能开篇给了一条贯穿全文的主线：**Swift 是渐进披露的语言——从最简单、最静态、最单线程的做法开始，只在你指得出理由的地方才去购买动态性（并发、引用语义、存在类型、不安全指针）。** 然后它把这变成一个必须记住的默认值阶梯表：数据用 `struct`/`enum`，只有需要身份/共享/继承才降到 `class`；抽象先用具体类型，跨类型重复了才提协议；多态先用 `some P`，需要异构存储才用 `any P`；执行先留在主 actor 同步代码，**profile 出卡顿**才降到 `async` → `@concurrent` → `actor`；内存先用 `Array`/`String`，profile 出成本才用 `InlineArray`/`Span`；安全先用安全 API，C 互操作或实测热路径才用 `Unsafe*`。

最要紧的是**第 3 节并发**，技能自己说这是「agent 最常搞错的一节，因为模型在 6.2 变了」。它给了严格顺序、不许跳步的四级递进：① 全部单线程跑在主 actor（对多数 App 就够了）；② 用 `async`/`await` 隐藏延迟（网络、磁盘），仍然没有你自己的并发——`URLSession.data(from:)` 这类 SDK 会替你卸载；③ 只有在 Instruments 显示卡顿后，用 `@concurrent` 把**你自己的**重活移出主线程；④ 只有当主 actor 上的状态太多、任务被迫反复跳来跳去时，才用 `actor` 把**状态**移走。并且要先开对构建设置：每个项目都开 **Approachable Concurrency**；App 与 UI 模块设 **Default Actor Isolation = MainActor**（Xcode 26 新 App 项目的默认，能删掉大量 `@MainActor` 标注；包里写 `swiftSettings: [.defaultIsolation(MainActor.self)]`）；但**通用库不要设主 actor 默认**——库该发 `nonisolated` API，让调用方决定在哪跑。

改掉的那条规则说得很直白：**在 Swift 6.2 里，把函数标成 `async` 并不会把它移出当前 actor**，它在被调用的地方运行——这正是「最自然的写法」默认就没有数据竞争的原因。于是三个修饰各有含义：`@concurrent` 总是切到并发线程池（用在你的 CPU 重活上）；`nonisolated` 在调用处运行（**这是库 API 的正确答案**，因为决定权在调用方，且标在类型上会让所有成员都 nonisolated）；什么都不标就留在调用者的 actor 上。其余硬知识包括：`await` 是挂起点、会破坏原子性（挂起期间状态会变、还可能换个线程恢复，**每次 `await` 后要重新检查假设，绝不跨 `await` 持锁、绝不依赖线程局部存储**）；actor 只保证互斥不保证事务（**状态变更放进同步方法**，那是你的事务边界），经典 bug 是「查缓存 → await 下载 → 写缓存」两个任务重复下载互相覆盖；**actor 不是 FIFO**（它优先跑高优先级任务以避免优先级反转，需要顺序要用 task 或 `AsyncStream`）。

后面各节也都是同一路数：错误处理区分「可恢复错误 → `throw`」与「程序员错误 → `precondition`/`fatalError`」，并说明 `throws` 就是 `throws(any Error)`、不抛就是 `throws(Never)`；`Sendable` 一节给出**遇到数据竞争错误的排查顺序**（第一位永远是「不要共享它」，绝大多数真实错误都死在这里；其次才是值类型、actor 隔离，最后才是 `Mutex`/`Atomic`/`@unchecked Sendable`），并强调**多数 model class 应该既不 `@MainActor` 也不 `Sendable`**，故意保持非 Sendable；结构化并发一节要求 `async let` 用于固定数量的子任务、`withTaskGroup` 用于动态数量、**子任务无返回值时用 `withDiscardingTaskGroup`**，`Task { }` 只在生命周期不属于任何作用域时用，`Task.detached` 几乎永远不用，并且**并发要设上限**（不要对无界列表每项起一个子任务）；SwiftUI 一节解释 `View` 本身是 `@MainActor` 隔离的（所以几乎不用写 `@MainActor`），但 `visualEffect`、`Shape.path(in:)`、`Layout`、`onGeometryChange` 会被刻意放到主线程外（信号是签名里的 `@Sendable`），**此时不要传 `self`，把需要的那一个值拷进捕获列表**。

性能一节先讲四个成本（函数调用、内存布局、分配、拷贝），然后明确「**先做算法层面的事**」：`Array.remove(at:)` 是 O(n)、放循环里就是 O(n²)，`removeAll(where:)` 总共 O(n)——技能说这两处曾经是**藏在漂亮代码后面的 100 倍以上回退**；链式 `map`/`flatMap`/`filter` 每一段都分配一个数组。然后是具体的杠杆：`final` 让动态派发变静态、结构体内联而类外置、`any P` 有 3 字内联缓冲（放不下就每次拷贝都堆分配）、`[MyModel]` 优于 `[any Model]`、`InlineArray<N, T>`（6.2）用于定长存储、`Span`/`RawSpan`/`OutputSpan`（6.2）取代 `withUnsafeBufferPointer`。ARC 一节的核心是「**对象的保证生命周期在最后一次使用处结束，而不是右大括号**」，所以依赖 `deinit` 何时运行是潜在 bug；`weak`/`unowned` 只用来断引用环，而且**对 weak 做可选绑定比强解包更糟**（把响亮的崩溃变成静默的错误答案）。

最后是测试、宏、日志、不安全代码、迁移和速查表。测试默认用 **Swift Testing**，XCTest 只在三件事上仍然是必需的（UI 自动化 `XCUIApplication`、性能指标 `XCTMetric`、必须用 Objective-C 写或捕获 ObjC 异常的测试）。

## 什么时候该用它

- 「帮我写/评审一段 Swift 代码，按现代写法来」
- 「升级到 Swift 6 之后一堆并发报错，怎么修？」
- 「App 卡顿，怎么判断该不该用 `@concurrent` 或 `actor`？」
- 「这个 `async` 函数为什么还跑在主线程上？」

- 「把这套 XCTest 迁到 Swift Testing」

## 什么时候别用它

- 不是 Swift（Kotlin/SwiftUI 之外的移动栈、Web 前端）——本技能只讲 Swift 语言与 Apple 平台生态。
- 做 React Native / Expo 上的动画或手势，用 `animate-expo`；Web 动效用 `animate`。
- 只是想要「最短最少的代码」这种精简风格约束，用 `ponytail`；要审查过度设计用 `ponytail-review`。
- 需要的是需求拆解或架构规划（`requirements-planning`）而非语言层写法。

## 依赖与前提

- 纯知识型技能，零依赖、不联网。
- **工具链基线是 Swift 6.3**（技能写作时标注为 2026 年 8 月的当前版本），内容以 **Swift 6.4** 为止。文中用 **⚠ 标记的条目是尚未发布的 Swift 6.4 特性**——提案已接受并在 main 上实现，可以据此规划，但今天写不了；用它之前要确认项目工具链，若目标是 6.3 及更早要退回旧写法。

## 注意事项与已知限制

- **不要写 `async` 又什么都不 await**：技能明确说「another reason not to make something `async` that has nothing to await」（异步函数的状态在按任务的 slab 分配器上、每个挂起点拆成部分函数，调用开销略高）。
- **`await` 破坏原子性**：每次之后重新检查假设；不跨 `await` 持锁（`DispatchSemaphore`、`NSCondition` 这类阻塞原语跨 `await` 是禁忌）、不跨 `await` 依赖 thread-local。
- **actor 只互斥不事务，也不是 FIFO**；状态变更要放进同步方法，`await` 处不能留下不一致状态。
- **取消是协作式的**：取消只设个标志，什么都停不下来；要在**开始昂贵工作之前**检查 `Task.isCancelled` / `try Task.checkCancellation()`；用 `withTaskCancellationHandler` 时注意 handler 立即且并发地与主体运行，它动的状态需要真正的同步（原子量或锁，**不能用 actor**，因为你无法保证 actor 上的顺序）。
- **continuation 的契约是「每条路径恰好 resume 一次」**：不 resume 会永久挂起调用方，resume 两次是致命错误。
- **不要无界 fan-out**：不要对无界列表每项起一个子任务。
- **多数 model class 故意既不 `@MainActor` 也不 `Sendable`**；`@unchecked Sendable` 是编译器无法验证的承诺，只留给有真实内部同步的类型；`nonisolated(unsafe)` 是最后手段，不是用来关警告的。
- **不要靠 `deinit` 的副作用**（打点、发全局事件）来保证正确性——它和优化器决策赛跑。
- **不安全代码不等于会崩溃**：「不安全」意味着 API 无法完整校验输入，违约是**未定义行为**；安全 API 反而会**有意地 trap**。
- **迁移时绝不把大重构和开启数据竞争安全合在一起做**，否则两样都得回退。
- 6.4 的 ⚠ 特性在 6.3 上写不了，别不查工具链就用。
- 技能只给写法指导，不自动改你的代码。

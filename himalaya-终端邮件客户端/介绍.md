# 终端邮件客户端（himalaya）

> 一句话：让 AI 直接在命令行里帮你翻收件箱、读信、写信、回信、归档和下载附件，用的是你自己邮箱的账号。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 可用，但**本机还没装 himalaya 命令行程序**，用之前必须先装） |
| 外部依赖 | 需要装 `himalaya` 命令行程序；需要你邮箱的 IMAP 收信 / SMTP 发信授权码；需要一个密码保管方式 |
| 产出 | 邮件列表、单封正文、原始邮件全文、结构化 JSON 输出；也可以替你发出邮件（有重复发送的坑，见下） |
| 入选理由 | 这是把「邮箱」这一整块工作交给 AI 操作的标准做法：支持多账号、附件、脚本化，且能输出机器可读的 JSON |

## 它解决什么问题
邮箱里要找一封三个月前的邮件、要批量归档、要把附件另存出来，用网页版点半天。
而 AI 本来会读会写，却伸不进你的邮箱。
himalaya 是一个纯命令行的邮件客户端，装好并配好账号以后，AI 就能像操作本地文件一样操作你的邮箱：列文件夹、搜邮件、读正文、写新信、回信、转发、移动、删除、打标记、下附件全都能做；加 `--output json` 还能拿到方便程序处理的结构化结果。

## 什么时候该用它
- 「看看我收件箱里有什么新邮件」
- 「帮我找一下 John 上周发来的那封关于会议的邮件」
- 「读一下第 42 封邮件给讲给我听」
- 「帮我回一封，就说我周四之前给他答复」
- 「把这几封邮件移到 Archive，附件下载到下载目录」

## 什么时候别用它
- 你还没装 himalaya，也不打算装——这个技能只是使用说明，程序本身得单独安装。
- 你的邮箱只支持网页登录、没开 IMAP/SMTP（或者公司 IT 禁了第三方客户端），那就接不上。
- 你要发的是排版复杂的图文邮件——它的富文本要用一套叫 MML 的专门写法，有学习成本。
- 你不想把邮箱授权码交给命令行程序保管——虽然技能推荐用 `pass` 或系统钥匙串，但凭据终究要落地到本机。

## 怎么开口
- 「列一下我收件箱里最近的 20 封邮件」
- 「搜一下这个主题的邮件，然后把它们归档」
- 「帮我写封邮件发给 xxx@example.com，主题是会议改期，正文简洁一点」
- 「把第 42 封邮件转发给 xxx@example.com，并下载它的附件」

## 输入 / 输出
它会向你要：装好的 himalaya 程序、一个配置文件（默认在 `~/.config/himalaya/config.toml`）、以及你邮箱的服务器地址、端口、加密方式、登录名和授权码。
它会给你：终端里直接可读的邮件列表和正文；需要给程序看的时候，用 `--output json` 输出结构化数据；发信/回信/转发则通过管道把写好的邮件喂给 `himalaya template send`。附件用 `himalaya attachment download <邮件号>` 存到本机。
邮件编号是相对于当前文件夹的，换了文件夹要重新列一次才能拿到新的编号。

## 依赖与前提
- 必须先安装 himalaya 程序本身（三种装法：官方一键脚本装预编译版、macOS 用 Homebrew、或者用 Rust 的 cargo 从源码装）。
- 必须有一份配置文件和可用的 IMAP/SMTP 凭据。密码建议交给 `pass` 或系统钥匙串，配置里只写「去哪个命令取密码」。
- 配置向导 `himalaya account configure` 需要交互输入，必须有伪终端；非交互环境下直接手写配置文件更稳。
- 网络要能连上你邮箱的 IMAP（一般 993 端口）和 SMTP（一般 587 端口）。
- 本机现状：`himalaya` 命令不存在，`~/.config/himalaya/` 目录也不存在，属于从零开始。

## 内部结构
- `SKILL.md` 303 行：前置条件与安装、配置文件怎么写、常用操作（列文件夹、列邮件、搜索、读、回、转发、新建、移动、复制、删除、标记）、多账号、附件、输出格式、调试方法、技巧。
- `references/configuration.md` 227 行：配置文件详解，含最小 IMAP+SMTP 示例、密码的几种存法、Gmail 与 iCloud 的完整配置、文件夹别名映射、多账号。
- `references/message-composition.md` 199 行：MML（一套给邮件排版用的标记语法）的写法，含多部分邮件、附件、内嵌图片、标签速查，以及从命令行写/回/转/发的各种方式。
这么拆是因为：主文件要短，日常操作一眼能查；配置和排版是两块独立又啰嗦的知识，放边上按需翻，避免主文件被配置样例淹没。

## 注意事项与已知限制
- **本机尚未安装 himalaya**，且没有任何现成配置；这个技能当前只是一份操作手册，装好之前一次都跑不了。
- **真实事故（技能里专门写了警告）**：文件夹别名的写法在不同版本间变过。旧文档里用的单数形式子表 `[accounts.NAME.folder.alias]`，在新版本里会被**静默忽略**——配置文件能正常解析、不报错，但别名根本没生效，所有查找都退回默认名字。在 Gmail 上后果是：SMTP 其实已经把信发出去了，但「保存到已发送」这一步失败，`himalaya message send` 返回非零退出码；任何看到非零码就重试的调用方（AI、脚本、人）会把整封邮件连 SMTP 一起重发一遍，**收件人收到重复邮件**。正确写法是复数、点号分隔的 `folder.aliases.sent = "..."`，Gmail 要映射到 `[Gmail]/Sent Mail`。
- 写邮件、回信、转发推荐用管道喂内容（`cat << EOF | himalaya template send`），不要用交互式编辑器模式——交互模式需要伪终端，还得预先知道用户机器上装了哪个编辑器。`message reply --all` 这类命令是交互式的，非交互环境下要用模板加管道的方式替代。
- 邮件编号只在当前文件夹内有效，换文件夹必须重新列。

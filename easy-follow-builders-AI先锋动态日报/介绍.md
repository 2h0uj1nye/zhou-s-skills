# AI 先锋动态日报（easy-follow-builders）

> 一句话：把 AI 圈最会做事的那几十个人最近在 X、播客和官方博客上说的话，翻成中文、整理成一份能刷着看的日报。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；技能自带 Node 脚本，本机 Node v24.20.0 可跑） |
| 外部依赖 | 默认零依赖。只有想让它自动推送到手机时，才需要 Telegram 机器人 token 或 Resend 邮箱 key |
| 产出 | 一份中文日报：每条内容固定「中文总结 + 中文全文翻译 + 推荐理由 + 原文链接」四段，播客全文翻译另放文末附录 |
| 入选理由 | 它盯的是真在一线做产品、开公司、做研究的人，不是二手转述；中文全文翻译替你把英文播客和长文读掉了 |

## 它解决什么问题
你想跟上 AI，但信息散在几十个 X 账号、六档播客、两家公司的官方博客里，播客一集两小时，还全是英文。
自己逐条翻，一天就没了；不翻，又怕漏掉真正的变化。
这个技能把这些信源最近的内容集中抓下来，逐条做中文总结、把英文原文整段翻成中文、附上推荐理由和原文链接，你花几分钟就能扫完。

## 什么时候该用它
- 你打了 `/ai`，或者直接说「给我来份 AI 日报」
- 「看看最近的新闻」「最近有啥新鲜事」
- 「AI 圈最近发生了什么」「最近 AI 圈在聊啥」
- 「最近 AI 圈有啥值得看的」
- 「帮我看看那些 AI 大佬最近在说什么」

## 什么时候别用它
- 你要查的是一件具体的事（某人某公司到底有没有发过某个公告），而这件事不在它的固定名单里——它是固定信源的日报，不是全网搜索。
- 你要读英文原文——它默认只给中文，成品里不展示英文原文。
- 你想自己增删追踪名单——名单由上游统一维护，用户改不了。
- 你在完全断网、连网页抓取通道都被封的环境里（正常能上 GitHub 就行）。

## 怎么开口
- 「来份 AI builders 日报」
- 「看看最近 AI 圈发生了什么」
- 「最近 AI 圈有啥值得看的」
- 「日报改成每周一发，早上八点，时区上海」

## 输入 / 输出
第一次用，它会拉着你走一遍配置向导，问你要：每天还是每周、几点、你的时区、日报语言（中文／英文／中英对照）、投递方式（直接显示在对话里／Telegram／邮箱）。
之后它不再问，直接给成品。成品格式是死规定，四段顺序不能变：① 中文总结 ② 中文全文翻译（逐段翻译全文，不是摘要）③ 推荐理由 ④ 原文链接。
播客因为太长，正文只放总结、理由和链接，整篇翻译挪到文末的「📼 播客全文翻译（附录）」。每条内容都必须有链接，没链接就不写进去。

## 依赖与前提
- 默认模式（日报直接显示在对话里）：**什么都不用装**。
- 想自动推送到手机：要去 Telegram 找 @BotFather 拿一个机器人 token，或者注册 Resend 拿一个邮件发送 key；同时要在 `scripts/` 里执行一次 `npm install`（只装一个 dotenv）。
- 需要能访问 GitHub 的 raw 文件地址。本机实测三个中央数据源都返回 200（约 15KB / 65KB / 4.6KB），抓取正常。
- 本机 `~/.follow-builders/` 目录还不存在，所以第一次运行必然要过一次向导，配置会写在这个目录里。

## 内部结构
- `SKILL.md` 562 行：平台判断、首次配置向导、每次出报的「抓取 → 改写 → 投递」流程、改设置的处理方式、以及怎么把整个文件夹拷给别人用。
- `config/feeds.json` 只存 3 个中央数据源地址（推文、播客、博客各一）；`config/default-sources.json` 是名单：26 个 X 账号、6 档播客、2 个官方博客。
- `prompts/` 7 个文件共 186 行：分别规定日报的整体结构、播客/推文/博客怎么总结、怎么翻译、怎么翻全文、推荐理由怎么写。
- `scripts/prepare-digest.js` 把抓取、读配置、读提示词全做完，吐出一大坨 JSON 给 AI；`scripts/deliver.js` 负责推送。
这样拆是因为：抓数据是机械活，交给脚本才能每次一致；写作风格和结构交给提示词文件，改风格不用碰代码，也不用改技能本身。

## 注意事项与已知限制
- **名单不能自己改**。想加人加播客，只能去上游仓库提建议。
- 用系统 crontab 做定时投递时，命令是「抓取脚本直接管道给投递脚本」，**绕过了 AI**，所以那一次发出去的是原始 JSON，不是排好版的中文日报。想要完整日报得手动触发，或者换成 OpenClaw 那种常驻 agent。
- 技能包里的 `scripts/package.json` 声明了 `generate-feed` 命令，但 `generate-feed.js` 这个文件没有随包，那条命令跑不通（这是上游自己做数据用的入口，不影响出报）。
- 脚本抓取时会在技能自己目录下建 `.cache/` 缓存；整个文件夹拷给别人时，`.cache/` 和 `node_modules/` 都不用带。
- 覆盖面有边界：播客每天最多一集，官方博客只跟了 Anthropic 和 Claude 两家。
- 源站内容都是外部抓来的，AI 只负责改写和翻译，不联网补料；它被明确禁止编造内容。

## 来源
上游移植。核心来自 GitHub 项目 `zarazhangrui/follow-builders` 的技能，本目录把它整理成自包含、路径无关的一份：提示词全部随包（`prompts/` 优先于上游线上副本），并以中文四段式作为默认产出。信源名单同样由上游统一维护。

# 模式 A：反问澄清（Interrogation）

把用户脑子里的隐性判断逼成显式文字。目标不是问得多，而是**问到能停**。

## 一、先复述，再提问

开始前先写一句复述：

> 我理解你要的是：<一句话>。如果不对，先纠正我。

理由：不复述就提问，你问的是自己脑补的那版需求；用户会在两个不同的问题上给你答案，最后谁也说不清分歧在哪。

## 二、五类问题

### 1. 伪需求识别

**信号**（命中任一就重点拷问）：

- 需求里出现具体技术、框架、控件名（“加个弹窗”“上 Redis”“用微服务”），但说不出触发条件与不变式。
- 描述的是可观测症状（“页面很慢”“用户总填错”），不是根因。
- 出现无基线的形容词指标（“更快”“更智能”“更好用”）。

**拷问句**：

- “如果去掉这个方案，什么问题依然存在？”——依然存在 → 那是伪需求，真正的需求是那个问题。
- “这个现象最先在什么操作路径下出现？能给一条可复现的步骤吗？”
- “‘更快’是相对哪个基线、用哪个指标测？”

**处理**：把伪需求降级为“候选方案”记在规格的备注里，把背后的真问题升级为需求条目。

### 2. 约束与偏好

**判据一句话**：问“违反这条，方案是被**否决**还是被**扣分**？”否决=约束；扣分=偏好。

| | 约束 | 偏好 |
|---|---|---|
| 可协商 | 否 | 是，有多档 |
| 典型 | 合规、预算、deadline、已有接口、硬件限制、数据不可出境、向后兼容 | 技术选型习惯、响应时间档位、UI 风格、目录结构 |
| 写法 | 来源 + 可第三方验证的判据 | 选定档位 + 为什么选它 |

**拷问句**：

- “如果换成 X 且成本更低，你会接受吗？”——会 → 刚才那条是偏好。
- “这条是谁提的要求？有文号/合同/接口文档吗？”——找不到来源 → 大概率是偏好。
- “怎么验证它被满足了？”——答不上来 → 不可作约束，只能当风险。

### 3. 失败模式与边界

不要让用户“想全面”，给他清单勾选（勾选比开放式作答有效得多）：

- 输入侧：空值 / 超长 / 极值 / 非法格式 / 重复提交
- 时序侧：并发 / 超时 / 部分成功 / 乱序 / 重试
- 权限侧：无权限 / 越权 / 会话过期
- 依赖侧：下游不可用 / 下游慢 / 下游返回脏数据
- 人为侧：误操作 / 找不到入口 / 中途放弃

**拷问句**：“这几种里哪些必须处理，哪些明确不管？”——明确不管的写进 outOfScope。

### 4. 验收预演（最有价值的一类）

**拷问句**：

- “这个东西做完的那天，你用什么动作确认它成了？”
- “如果我只做到 80%，你最先砍哪部分？”
- “什么情况下你会说‘这不是我要的’？”

把答案直接改写成验收标准句式（见 `spec-template.md`）。

### 5. 范围与取舍

**拷问句**：“这次明确不做的是什么？”——outOfScope 为空说明范围还没定。

## 三、提问节奏

- 一次 3–5 个问题，按“阻塞程度”排序，最影响验收的排第一。
- 给候选选项 + 默认建议，而不是开放式问答：`A) … B) … 我建议 B，因为…`。
- 同一问题最多追问 2 轮；第 3 轮改成“这题我按 X 假设，影响是 Y，你可以之后推翻”。
- 不要一次抛出 20 问；那会让用户放弃作答，等于没问。

## 四、停止判据（细则）

同时满足才算澄清够了：

1. 每条功能点能写出 ≥1 条可判定验收标准（正例 + 否定用例）。
2. 每条约束有来源且可被第三方验证；偏好有明确档位。
3. 无开放枚举词残留（等等 / 尽量 / 可能 / 视情况 / 友好 / 优秀）。
4. outOfScope 非空且经用户确认。
5. 所有未知均以【假设】标注，且附影响与复查触发点。
6. 剩余未知只影响实现细节，不影响验收判定。

**继续追问的信号**：仍在用形容词；两个目标互相冲突；出现“看情况”；阈值无人拍板。

## 五、降级：假设清单格式

用户答不上来、或明确说“你定”时，不要编造事实，转成假设。

```
| 编号 | 假设内容 | 依据 | 若为假的后果 | 复查触发点 |
|------|----------|------|--------------|------------|
| H1 | 单租户部署，不做多租户隔离 | 用户原话“先给内部用” | 数据模型需重做 | 首次外部客户接入前 |
| H2 | 峰值并发 ≤ 200 | 行业惯例 + 现有用户量级 | 需引入缓存/限流层 | 上线后首月监控超阈值 |
```

影响面分级：

- **高**（改假设要重做，如交互模型、数据模型）→ 用户必须确认才能进入写规格。
- **中/低** → 可带假设前进，但集中在规格顶部列出，并在拆卡片时转成卡片的风险字段。

## 六、反模式

- 停留在“帮我把需求问清楚”而不产出任何文档 —— 澄清记录本身就是产物。
- 用提问代替判断：明明能给出默认建议却把决策原样丢回给用户。
- 把“用户没回答”当成“用户没意见”，然后当成事实写进规格。
- 问完不收敛：无限轮次追问细节，却不检查停止判据。

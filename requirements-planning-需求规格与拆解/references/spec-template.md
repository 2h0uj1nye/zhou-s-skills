# 模式 B：规格模板（Spec Template）

直接复制骨架填写。**每一块都必须有内容或显式写“无”**，留空等于把问题推给下游。

## 骨架

```markdown
# 规格：<主题>

- 版本：v0.1 ｜ 日期：YYYY-MM-DD ｜ 作者：<谁>
- 一句话目标：<做完之后，谁获得什么能力>

## 0. 假设与风险（置顶）
| 编号 | 假设/风险 | 依据 | 若为假的后果 | 复查触发点 |
|---|---|---|---|---|

## 1. 功能列表

### 1.1 核心（砍掉则整个需求无意义）
- F1 <功能点> —— <判据：砍掉它，哪条验收会失败？>

### 1.2 次要（可延后，不破坏核心验收）
- F2 <功能点>

### 1.3 边界情况
- F3 <空值 / 极值 / 并发 / 超时 / 部分失败 / 重复提交 / 权限不足 / 依赖不可用>

## 2. 约束条件（不可协商，违反即方案不成立）

| 约束 | 来源（谁/哪份文件） | 第三方如何验证 |
|---|---|---|

## 3. 偏好与取舍（可协商，已选定档位）

| 偏好项 | 选定档位 | 选择理由 | 备选 |
|---|---|---|---|

## 4. 接口定义

| 字段/端点 | 类型 | 必填 | 取值范围/枚举 | 默认值 | 来源 |
|---|---|---|---|---|---|

| 错误码 | 触发条件 | 语义 | 客户端应有行为 |
|---|---|---|---|

幂等性：<是否幂等 / 幂等键>

版本兼容：<不兼容变更如何发布>

## 5. 验收标准
（每条：AC 编号 | 类型（正例/否定/边界）| 承接功能点 | 可判定命题 | 验证方式）

- <明确不做的项，及理由>

|---|---|---|---|
```

## 各块填写判据

### 功能列表分级

- 核心：砍掉它，某条既有验收标准会失败。
- 次要：砍掉它，核心验收全部仍通过。
- 边界情况：不是“少见的正常流程”，而是**异常输入与失败路径**。
- 禁止把“先写后端、再写前端”这类工序写进功能列表 —— 那是实现顺序。

### 验收标准：写成可判定命题

**句式**：

> 在 <前置条件> 下，当 <触发/输入> 时，<系统> 应 <可观测行为>，且 <可测量指标> 在 <阈值/范围> 内。

**唯一判据**：两个不同的人独立按这条标准执行，得到同一个 `passed` 或 `failed`。做不到就是没写完。

**正反例对照**：

| ✗ 不可判定 | ✓ 可判定 |
|---|---|
| 登录要安全 | 连续 5 次密码错误后，第 6 次提交在 1s 内返回 429；账号锁定 15 分钟，期间即使密码正确也返回 429 |
| 性能优秀 | 登录接口 P95 响应 ≤300ms（并发 50、样本 ≥1000 次） |
| 支持多种登录方式 | 支持且仅支持：口令、微信授权、企业 SSO 三种；未启用的方式入口不渲染 |
| 尽量不报错 | POST /login 缺 password 字段返回 400，body 含 `error.code = "MISSING_FIELD"` |
| 体验友好 | 首次进入 3 步内完成配置；每步提供返回上一层的入口 |
| 兼容主流浏览器 | iOS Safari ≥16、Chrome ≥110 完成全流程无未捕获 JS 异常 |
| 数据要一致 | 同一幂等键重复提交 10 次，最终仅产生 1 条记录，且第 2–10 次返回与首次相同的结果体 |

**强制规则**：

1. 阈值必须带**数值 + 单位 + 测量方式**（压测？日志？人工计时？）。
2. 每个功能点 ≥1 条否定用例（错误输入 / 权限不足 / 依赖不可用）。
3. 禁止开放枚举词：等等、诸如、必要时、主要包括、原则上。
4. 每条标注**验证方式**：自动测试 / 手工步骤 / 日志取证 / 压测。无法验证的条目不许进本节 —— 移到第 0 节当风险。
5. 验收标准编号 AC-n，供任务卡片引用。

### 约束 vs 偏好

- 约束表必须有“来源”和“第三方如何验证”两列。填不出来 → 它其实是偏好。
- 偏好表必须有“选定档位”。写“看情况”= 没定，退回模式 A。

### 接口定义必填项（最常被漏）

- 错误码表（含触发条件与客户端应有行为），不是只写“返回错误”。
- 幂等性：是否幂等、幂等键是什么。
- 重试语义：哪些错误可重试、退避策略、重试上限。
- 版本兼容：破坏性变更怎么发布、旧客户端怎么办。
- 字段级：类型、必填、取值范围/枚举、默认值、来源（用户输入 / 系统生成 / 上游）。

### 安全与脱敏

- 严禁写入真实口令、token、私钥、连接串、真实手机号/身份证/客户名。
- 一律替换为 `<PLACEHOLDER>` 或 `<从环境变量读取>`；示例值用明显的假值（如 `user@example.com`）。
- 发现用户原话含敏感信息时：不要复述原值，在第 7 节写明“已脱敏为 X，请确认原值不进入文档”。

### 变更记录

- 每次修改都追加一行：日期 / 改了什么 / 为什么 / 谁定的。
- 没有变更记录，任务卡片会在规格静默修改后失效且无人察觉。

# 战略顾问（strategic-advisor）

> 一句话：让 AI 换一副面孔——不是等你提问的助手，而是像顾问一样反过来一句一句问你，把你到底想要什么问清楚，最后给一份能照着做的行动计划。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH 技能。纯中文 Markdown 指令包，无平台限制，聊天里就能触发 |
| 外部依赖 | 零依赖：不装软件、不读配置文件、不联网、不调用其它技能 |
| 产出 | 两步：先一份结构化需求报告（请你确认），确认后给一份行动规划文档（Markdown 或单文件 HTML） |
| 入选理由 | 它反过来解决「你自己都说不清想要什么」这种最常见的困境；而且是少数敢明确说「达到足够把握前我只提问、不给方案」的技能 |

## 它解决什么问题

你心里有件事要做（学一门技能、换条路走、动手做个项目），但说不清目标、也说不出卡在哪，跟 AI 说两句就变成它在替你出主意，出的还是一堆跟你实际情况对不上的主意。这个技能把顺序倒过来：先由 AI 主动、一轮只问一个问题地把你的现状、真正动机、可用时间、手头资源、会踩的坑挖出来，边问边报「现在把握到几成」；等把握够了（设定是 95%）才出一份需求报告让你核对，你点头之后才给行动计划。它针对的是「信息太乱、不知道从哪开始」这类状态。

## 什么时候该用它

- 「我想换个方向，但不知道从哪下手，你问我吧。」
- 「信息太乱了，帮我理一理我到底想干什么。」
- 「你来当我的顾问，你主导，别我问你答。」
- 「接下来半年我想学点东西，但还没想好学什么，帮我理清。」
- 直接说 `/战略顾问` 或 `/advisor`。

## 什么时候别用它

- 你已经想清楚要什么、只差一个具体做法——比如「帮我写个脚本」「这个报错怎么修」，那属于直接干活，不需要被拷问十几轮。
- 你只是想让 AI 给个建议或列个清单，不想被反问——它设计上就是单轮单问、逐层推进的，节奏慢是故意的。
- 你赶时间、只想快点拿到结果——它要先做 7 层探索；虽然你说「够了」它会立刻停并交出当前理解，但产出的把握度也会相应低。

## 怎么开口

- 「你当我的战略顾问，问我问题，帮我把这件事想清楚。」
- 「我想用 90 天学一项新技能，你从头问我。」
- 「接下来只做一件事的话，我该做什么？你来主导提问。」
- `/advisor`（然后老实回答它每个问题）

## 输入 / 输出

**它向你要**：全部是你自己的情况——最终最想解决的那个问题、目标对你意味着什么、现在的基础和能力、多方向之间的主次、每周和不同日子能投入多少时间、设备和预算这类资源约束、想拿到什么成果、给谁看、以及「如果失败最可能因为什么」。用户上传图片（比如电脑配置截图）时它会读取并算进约束里。

**它给你什么**：

- 过程反馈：每轮结束报一次当前信心度（比如 `当前信心度：65%`），每 2–3 轮复述一次已经理清的内容。
- 阶段一：**结构化需求报告**，7 个固定部分——需求概述、需求类型、目标与范围（含排除范围）、关键约束、阶段成果与受众、交付形式、风险与预防。末尾请你确认。
- 阶段二（你确认后）：**行动规划文档**，含现状画像、用 Mermaid 画的能力跃迁图、免费优先的工具资源清单、分阶段周计划（每周有主题 / 平日任务 / 集中任务 / 产出物 / 防卡策略）、作品集或成果规划、风险预防矩阵、每周自检清单。形式是 Markdown 或单文件 HTML。

## 依赖与前提

无。不需要任何外部软件、账号或配置。要看 Mermaid 流程图和深色主题排版效果，用能渲染 Markdown 的查看器或浏览器打开生成的 HTML 即可；这与技能本身无关。

## 内部结构

单文件技能，只有 `SKILL.md`，186 行，**没有 references 目录、没有 scripts**。内容分八块：核心理念、触发条件、与另一个技能的区别对照表、7 条核心原则、执行流程图、七层深度探索框架（L0 核心目标 → L7 风险预判，每层标注典型提问数和信心度权重）、信心度评分表（7 个维度加权）、两个输出阶段的详细结构，最后是注意事项。

这样拆的原因：它是一段「怎么跟人对话」的流程规范，七层问题是递进关系，拆开反而容易断线；单文件能保证从提问到出报告的节奏一致。

## 注意事项与已知限制

- **追问阶段不给方案**：把握度到 95% 之前它只提问。如果你反过来问「那我该怎么办」，它会继续按流程走。
- **一次只问一个问题**：这是硬规定。你可以嫌慢，但这是它保证不问偏的前提。
- **95% 是它自评的数，不是客观指标**：信心度由 AI 自己按 7 个维度估分，你答得含糊它也可能估得偏高，看到数字别当成准确测量。
- **你说停就停**：说「够了」「直接做吧」，它会立刻输出当前理解并标注还缺什么——但缺的部分会以假设形式进报告，后续可能被打回。
- **对比表已重指**：文件开头原有一张与 `requirement-clarify` 的对比表，而该技能并不存在。现已改为与真实存在的 `requirements-planning` 对比（它负责「被动澄清需求并写成规格」，本技能负责「主动主导追问」），并写明了何时该选哪一个。
- **输出里的图是文字描述的图**：能力架构图用 Mermaid 语法写在 Markdown 里，查看器不支持渲染时你只会看到一段代码。

## 来源

单文件独立技能，文件内没有合并或移植的标注。它是把「以提问为主的澄清流程」写成了固定套路（七层探索 + 信心度评分 + 两阶段输出）。按移交说明，它此前引用的两个 references 文件根本不存在，还挂着一个图片生成工具和一个 html-report 技能，这些依赖已经全部清掉：现在全文没有任何 references 引用，输出明确限定为 Markdown 或单文件 HTML，且第 170 行还专门写了一句「不要在无图像生成能力时假装有封面图」，正是这次清理留下的痕迹。核实结果：目录下确实只有 `SKILL.md` 一个文件，正文里也搜不到任何外部技能或图片工具的调用。

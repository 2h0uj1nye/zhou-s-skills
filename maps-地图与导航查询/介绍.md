# 地图与导航查询（maps）

> 一句话：告诉它一个地名或一串坐标，它帮你查位置、找周边、算路线、报时区，全程用免费公开地图数据，不用注册账号。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测；网络受限，见下方"注意事项"） |
| 外部依赖 | 零依赖——只用 Python 3.8+ 自带的标准库，不用 pip 装任何东西；但必须能上网访问公共地图服务 |
| 产出 | 一段结构化文本/JSON：坐标、完整地址、周边地点清单（带距离和地图链接）、路线步骤、时区与当地时间 |
| 入选理由 | 8 个命令就覆盖了"位置"类几乎全部日常需求，不需要 API key、不需要安装，随手就能用 |

## 它解决什么问题

平时想问"这附近有药店吗""走过去要多久""这个坐标是哪儿"，通常得打开地图 App 手动点。在聊天里、在终端里、在写脚本的时候，这种需求很常见却不好办：要么切窗口手动查，要么付费调地图厂商接口。这个技能把整套查询变成了几条命令行，随问随答。

## 什么时候该用它

- "帮我找一下时代广场附近有什么咖啡馆"
- "这几个数字是个位置坐标，附近有医院吗？"
- "从埃菲尔铁塔走到卢浮宫要多久？"
- "巴黎和东京现在各是几点？"
- "这个地方的经纬度是多少？"

## 什么时候别用它

- 要的是实时路况、公交到站时间、打车预估车费——它用的是公开路网数据，没有这些。
- 要做逐条语音级导航、要地图截图或路线图图片——它只返回文字步骤和数字。
- 需要精确的门牌号级地址（尤其是中国国内地址）——公开地图的地址覆盖不保证。
- 单位的纯内网环境或完全断网——它每条命令都要联网，且目前有半个功能已经不可用（见下）。

## 怎么开口

- "帮我找一下纽约时代广场附近的餐厅，要 10 家，按距离排。"
- "我发个坐标给你：48.8584, 2.2945，附近 2 公里内有药店吗？"
- "从巴黎开车到里昂多远、要开多久？"
- "给埃菲尔铁塔到卢浮宫的步行路线，一步一步说。"

## 输入 / 输出

它向你索取的东西随问法而变——一个地名、一条地址、两个坐标，或地名加目的地。没有强迫性必填项，但有一条硬规矩：查周边时必须给它**坐标**或**一个地名**（用 `--near` 传地名时它自己去查坐标），两个都没有就没法工作。

输出是结构化数据，不是散文。周边查询每条结果含：名字、地址、经纬度、距离多少米、一个可直接点开的地图链接、一个"从这儿出发去那儿"的导航链接，数据里有的话还带菜系、营业时间、电话、网站。路线查询返回分步说明：第几步、往哪走、多少米、多久、走哪条路、什么动作（直行/转弯/到达）。

## 依赖与前提

软件上什么都不用装，Python 3.8 以上即可（本机是 Python 3.12）。不需要 API key，不需要账号。前提只有一个：网络能连上 OpenStreetMap 系的公共服务。这一点在本机是部分不成立的。

## 内部结构

`SKILL.md` 共 206 行，讲清 8 个命令怎么用、参数怎么写、坑在哪，外加一节本机网络实测表。真正的实现全在 `scripts/maps_client.py`（1311 行）：8 个命令各一个函数，共用一个带重试和"主备镜像轮换"的 HTTP 层。之所以这么拆，是因为说明文档要短到能一次读完，而命令的细节（46 个分类各自对应哪些地图标签、重试次数、限速）只有代码里放得下、也只该由代码知道。

## 注意事项与已知限制

**本机实测（2026-09，Ubuntu 24.04 / 中国大陆网络）——这是最重要的一条：**

| 依赖服务 | 实测 | 影响 |
|---|---|---|
| Overpass 主站 `overpass-api.de` | ✅ 通（我复测：真实查询返回 200、拿到结果） | 按坐标找周边可用 |
| 备用镜像 `overpass.kumi.systems` | ❌ 实际不可用（连接能建立，但查询读超时；我复测确认） | 主站挂了就没有退路 |
| Nominatim 地理编码 `nominatim.openstreetmap.org` | ❌ 网络不可达（我复测：Network is unreachable） | **地名转坐标、坐标转地址全部不可用** |
| OSRM 路线规划 | ✅ 通（SKILL.md 原文写"未测"，我补测：返回 200） | 距离与路线可用 |
| TimeAPI.io 时区 | ✅ 通（我补测：返回 200） | 时区查询可用 |

也就是说，**目前只有一半功能真的能用**，而且比"一半"更要命：命令说明里推荐的 `--near "地名"` 走的正是 Nominatim，所以在当前网络下找周边**必须自己先给坐标**，不能让脚本自己查。碰到 `search`/`reverse` 卡住或报连接错误时不要反复重试——SKILL.md 明确要求直接告知用户该服务在此网络不可达。

其他真实的坑：主站限速每秒 1 次请求（脚本已自动处理，但多分类查询会明显变慢）；OSRM 路网在欧洲、北美覆盖最好，其他地区可能不准；路线查询的目的地必须用 `--to` 参数、不能直接写在后面；单独给一个邮编可能全球范围产生歧义，最好带上国家或省份；营业时间来自众包数据可能过期，拿不准时应另用网络搜索核实。

**一处原文自身不一致（值得留意）：** `SKILL.md` 开头写"44 POI categories"，正文里写"46 categories"。我数了脚本里真实注册的分类，是 **46 个**——所以开头的"44"是笔误。

## 来源

上游移植技能，作者 Mibayy，MIT 协议，原始 `description` 是"Geocode, POIs, routes, timezones via OpenStreetMap/OSRM."。它是**吸收合并**关系：元数据里写明本技能替代（supersedes）了旧的 `find-nearby` 技能，旧技能的全部功能都被现在的 `nearby` 命令覆盖，连 `--near "<place>"` 写法和"一次查多个分类"都保留了。本机使用时额外增补了一节中文网络实测表，并把文档里写死的安装路径改成"技能安装目录"占位。

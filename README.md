# AI SKILLS DSH · 精选技能集

这份文件夹里是 **32 个技能**，分两辑，每一个都在这台机器（Ubuntu 24.04）上验证过：名字合法（全小写 kebab-case）、说明不超过宿主 500 字符上限、没有指向不存在文件的死链、没有用错宿主不认识的功能名。

- **第一辑 · 通用技能池**（19 个）：从 82 个技能里筛出来的，覆盖面杂，什么都有。
- **第二辑 · Emil Kowalski 设计与动效**（13 个）：来自 [emilkowalski/skills](https://github.com/emilkowalski/skills)，专治"界面差点意思"——都是作者在 Vercel、Linear 做设计工程的私域经验。

- 目录名格式：`英文名-中文名`
- 每个目录里：`SKILL.md`（技能本体）、`介绍.md`（大白话说明书）、以及该技能依赖的 `references/`、`scripts/`、`templates/` 等资源
- 技能本体是完整包：**单独拿走一个 `SKILL.md` 会导致它引用的资源缺失**，请整个目录一起复制

## 二、怎么装

技能放在宿主会扫描的目录里就会自动生效，不需要重启。安装根目录有两个位置：

- 用户级：`~/.dsh/skills`（所有项目都能用）—— **这 32 个已经装好了**
- 项目级：`<项目目录>/.dsh/skills`（只在那个项目里生效）

宿主扫描的是**两级结构**：`<根目录>/<任意目录名>/SKILL.md`，或者直接平铺的 `<根目录>/<名字>.md`。

```bash
# 推荐用法：复制过去时把目录名改成 SKILL.md 里的 name，最不容易出错
mkdir -p ~/.dsh/skills
cd "/media/zhou/软件1/AI SKILLS DSH"
for d in */; do
  name=$(grep -m1 '^name:' "$d/SKILL.md" | sed 's/^name:[[:space:]]*//' | tr -d '"'"'"'')
  cp -r "$d" ~/.dsh/skills/"$name"
done
```

**唯一硬性要求**：`SKILL.md` 里 `name:` 那行的值必须是**全小写、用连字符连接的英文**（`kebab-case`，例如 `humanizer`、`ponytail-review`）。写成中文、带空格或大写，技能会被**静默跳过**——不报错、不提示，就是不出现。第一辑的原池子 82 个里有 2 个就死在这里。

**第二条容易踩的坑**：`description` 超过 500 字符会被从尾部截断，而截掉的可能正好是触发词。第二辑里 `mobile-native`（原文 738 字符）和 `animate-expo`（523）都超了，装机时已压到限内。

目录名本身不参与识别（宿主只认 frontmatter 里的 `name`），所以中文文件夹名不会影响加载——上面脚本改成英文名只是为了让磁盘上整齐、也便于排查。

装好后可以用一句话验证：直接说"列出你有哪些技能"，或者试着触发一次。

### 第二辑的额外说明：3 个技能不会自己触发

`pick-ui-library`、`prototype`、`review-animations` 在原包里带 `disable-model-invocation: true`，意思是**只在你显式点名时才会跑**，模型不会自作主张调用它们。这不是装坏了——是作者故意的，因为这三个技能一旦乱触发会很吵（比如你随口提一句 UI，它就把整个项目评审一遍）。

要用就直接点名：

```
/pick-ui-library 选个图表库
/prototype 给我三个版本的定价卡片
/review-animations 审一下我这次的动效改动
```

## 三、怎么用

不用记技能名，直接说人话就行（上面那 3 个除外）。技能说明里写了各自的触发场景，例如：

- "这段文字帮我改得像人写的，别一股 AI 味" → `humanizer`
- "这个需求帮我理清楚，再拆成能干的活" → `requirements-planning`
- "事情太多不知道先做哪个" → `mental-models-lens`
- "照这个风格做个落地页，给我几种方案对比" → `design-toolkit`
- "最近 AI 圈有什么值得看的" → `easy-follow-builders`
- "这个下拉菜单打开太快了，帮我调一下手感" → `animate`
- "我们整个项目的动效都有点生硬，看看怎么改" → `improve-animations`
- "这个页面在手机上点起来很别扭" → `mobile-native`
- "弹出框打开时那个弹一下的效果叫什么" → `animation-vocabulary`

## 四、已知限制（实测）

| 技能 | 限制 |
|---|---|
| `maps` | 本机网络实测：POI 查询（Overpass）✅、路线规划（OSRM）✅、时区（TimeAPI）✅，但**地理编码/反查地址（Nominatim）不可达**。最要紧的是：主推用法 `nearby --near "地名"` 背后要先把地名转坐标，所以**查周边必须自己给经纬度**（`--lat --lon`）。备用镜像也不是网络问题，是查询读超时 |
| `himalaya` | CLI 未安装，技能只是手册，装了才能用 |
| `easy-follow-builders` | 首次运行需要过一遍配置向导，配置写在 `~/.follow-builders/` |
| `design-md` | 校验与导出依赖 `npx @google/design.md`，需要联网（本机实测可运行，v0.4.0） |
| `arxiv` | arXiv 会对密集请求临时限流（返回 406）。脚本已内置 5 次退避重试、并把报错换成可读提示；若限流窗口超过约 1 分钟仍会失败，等 1-2 分钟再跑即可（已实测能返回真实检索结果） |
| `pretext` | 依赖 CDN 加载库文件，需要联网 |
| `kb-sync` | 只在 Windows 上可用；依赖本地配置文件与外部上传脚本，缺配置时会停下来等你 |
| 第二辑全部 13 个 | **技能正文是英文的**（原包如此，未翻译）。它们是设计/动效的方法论与规则，读得懂但不省事；`介绍.md` 是中文的，可以先看那个 |
| `animate-expo` | 面向 React Native / Expo 项目。本机（Linux）没有 Expo 工具链，可以当写作指导用，但**无法在本机跑起来验证** |
| `write-swift` | 面向 Swift 项目。本机没有 Swift 工具链，同样只能当写作指导 |
| `ask-sonner` | 需要已有的 React 项目；`API.md` 里是完整的 props 表，查具体参数时才有用 |
| `prototype` | 产出是多个可切换的 UI 版本（HTML），需要在浏览器里翻看对比 |

### 第二辑 · Emil Kowalski（13 个）

原包 13 个技能，**一个没筛、全部收录**，理由：

1. 原包里没有凑数的——13 个各有明确分工，且互相之间有边界声明（例如 `animate` 会告诉你"批评现有动效请用 review-animations"）。

3. 装机时只做了三类必要处理：给 `description` 前置中文触发句并压到 500 字符以内（超限的 2 个）、保留原包的 `disable-model-invocation` 语义、整包复制资源文件。**正文一字未改**。

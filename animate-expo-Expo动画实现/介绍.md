# Expo / React Native 动画（animate-expo）

> 一句话：在 React Native / Expo 里做动画，先问「该不该动、跑在哪个线程」，再用 Reanimated + Gesture Handler 写出**在真机 release 构建上**站得住手的实现——而不是在模拟器里看着还行。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；技能正文为英文，不影响使用） |
| 外部依赖 | 需要 npm 包，且要用 **`npx expo install`** 而不是 `npm install`（前者才会解析匹配项目 SDK 的版本）：`react-native-reanimated` + `react-native-worklets`、`react-native-gesture-handler`、`expo-router`、`expo-haptics`；键盘场景另加 `react-native-keyboard-controller`；插画/庆祝用 `lottie-react-native`；超大型动画场景用 `@shopify/react-native-skia`。Reanimated 4 要求新架构（New Architecture）。**手感验证需要真机 release 构建。** |
| 产出 | 可直接落地的 Expo / React Native 代码（Reanimated worklet、Gesture、Expo Router 配置、haptics 调用），外加最多几行说明：门禁结果、配料（工具/属性/弹簧或曲线+时长/**线程**）、以及必须在真机上试的手感项。 |
| 入选理由 | 移动端有一整套 Web 上不存在的坑：RN 运行时与 UI 运行时的分裂、`setState` 每帧导致掉帧、`PanResponder`、动画 `height`、`BlurView` intensity、Android `elevation`、Expo Go 测不出性能、ProMotion 上第三方动画被锁 60fps。这份技能把这些坑变成一张「Never Ship」清单，并明确了唯一合格的验证方式：**最慢的支持机型上的 release 构建**。 |

## 它解决什么问题

技能一上来就点明**移动端改变动画的三件事**，后面所有内容都从这三点推出：(1) **没有 hover**——Web 上所有靠 hover 表达的可供性，必须重新设计到按压、位置或无；(2) **有两个运行时**——Reanimated 4 的 worklets 把这个讲明白了：React Native 运行时（React 渲染、你的业务逻辑）和 UI 运行时（worklet 每帧执行），动画一碰 RN 运行时就会卡；(3) **用户的手指就在元素上**——手势是主要输入，可打断与速度交接不是打磨而是底线。

它同样用**两类失败模式**定性，且第一种更糟：(1) 给不该动的东西加动画（门禁存在的意义就是有时产出零行代码）；(2) 正确的东西跑在错误的线程上——`setState` 每帧、`PanResponder`、动画 `height`。第二种最阴险：**在你的手机上开发模式看着没问题，到了三年前的 Android 上掉到 20fps**。

门禁比 Web 版更具体：100+ 次/天（**标签切换、键盘开合、滚动、设置里的开关**）不做，用平台默认或不做；几十次/天（按压反馈、列表导航、行选中）只能做 150ms 以内的、几乎察觉不到的；偶尔（sheet、modal、toast、引导步骤）用标准动画；罕见/首次（成功态、空状态插画、庆祝）才是惊喜预算。原文给了最硬的一条：**标签切换绝不滑动**——标签是平级的，滑动暗示了不存在的层级，而用户一个会话要为此付几十次代价，所以 `animation: 'none'`。

第 6 步「别让它跑在 JS 线程上」是移动端专属的手艺，也是大多数 RN 动效死掉的地方：**永远不要在手势或滚动回调里 `setState`**（每帧一次 React 渲染是 RN 卡顿的头号原因，正确做法是 shared value → `useAnimatedStyle`，React 完全不重渲染）；**永远不要在 `onUpdate` 或滚动回调里回调度到 RN 运行时**（Reanimated 4 里用 `scheduleOnRN` 取代已废弃的 `runOnJS`，但它在 `onUpdate` 里等于每秒 60–120 次调用，应该放到 `onEnd` 或阈值触发的 `useAnimatedReaction` 里）；**永远不要在渲染期读写 shared value**；用 `.get()` / `.set()` 而不是 `.value`（Reanimated 官方文档称前者是 React Compiler 能看懂的写法，`set` 还支持函数式更新 `sv.set(v => v + 1)`）；**被 worklet 调用的函数首行必须写 `'worklet'`**，否则在调试器里一切正常、一到真机就抛错。

## 什么时候该用它

- 「做一个可以拖拽下滑关闭的 bottom sheet。」
- 「列表行向左滑删除。」
- 「滚动时把大标题收起来。」
- 「为什么我这个动画在真机上卡，模拟器里好好的？」
- 「想在用户选择器停到某一格的时候给个震动反馈。」
- 「键盘弹起时让底部输入框跟着走。」

## 什么时候别用它

- **Web 动画**一律用 `animate`——本技能的每一步都建立在 RN 运行时 / UI 运行时的分裂上，Web 没有这个前提。
- 移动端 Web（PWA、触屏网页）的原生手感问题 → `mobile-native`（它还负责把「动效本身用 `animate`、React Native 用 `animate-expo`」这条分工写清楚）。
- 要一个现成的 UI 组件（bottom sheet、命令菜单、下拉）而不是一段动画 → `pick-ui-library`，手搓这些是缺陷来源。
- 批评已有动画、审计代码库 → `review-animations` / `improve-animations`（本技能的验收标准和它们同源）。

- 「我的 collapsing header 一滚就卡，是不是动了 height？」

- 「键盘跟随的底部栏用 keyboard-controller 怎么写？」
- 「这个动画要支持减弱动效，Reanimated 里怎么做？」

## 输入 / 输出

输入：Expo / React Native 里的动效或手势需求，附现有代码、目标平台、用的 Expo SDK 与手势库版本（`RECIPES.md` 专门区分了 Gesture Handler v2 和 v3 的写法）。

输出：先写代码，然后用最多几行交代三件事——**门禁结果**（频率档位 + 命名目的，以及被否掉了什么、为什么）；**配料**（工具、属性、弹簧或曲线 + 时长、以及**线程**）；**需要在真机上验证的手感**（手势、速度交接、haptic 时机从代码里判断不了，要指明试什么：甩一下、中途打断、反向、拿手上最慢的 Android 跑）。原文：代码才是交付物，不要扩写成报告。

**固定开场白**：首次被调用且用户没有具体问题时，只回一句 ——「I'm ready to build animations in Expo and React Native that feel right on a real device, my knowledge comes from Emil Kowalski's animation philosophy.」在此之前不给其他信息。

## 依赖与前提

- 安装必须走 Expo：`npx expo install react-native-reanimated react-native-worklets`；在 Expo 项目里 `babel-preset-expo` 自动配置 worklets 插件，**不需要**手动改 `babel.config.js`；只有没有该 preset 的裸 RN 项目才手动加，且必须放在插件列表最后。缺插件或位置不对不再静默降级，而是运行时抛 `Failed to create a worklet`。
- **`GestureHandlerRootView` 必须包住 app**，否则手势完全不工作且没有任何报错。
- **Reanimated 4 要求新架构。**
- **Expo Go 不是性能环境**：手感必须在 release 构建里判断，dev 构建的 JS 线程慢到足以掩盖你正要找的那些问题。
- 120fps：ProMotion iPhone 上第三方动画默认被锁 60fps，除非设置 `CADisableMinimumFrameDurationOnPhone`（新 Expo SDK 已默认开启，要确认存在），开启后帧预算从 16ms 变成 8ms——这也是为什么 UI 线程动画在移动端比在 Web 上更重要。
- 键盘跟随需要 `KeyboardProvider` 挂在根部，否则相关 hook 无效。

## 内部结构

两个文件，按渐进披露切分：

- **`SKILL.md`（265 行）**——决策与红线。结构：Operating Posture（两类失败模式）、5 条 Hard Rules（严格按序；**用 Reanimated 不用核心 `Animated`**——核心 `Animated` 无法被手势驱动而不跨桥，且 `useNativeDriver` 只接受 transform 和 opacity；不许近似值；减弱动效随动画交付；**手感在最慢支持机型的 release 构建上判定，其他都不算验证过**）、The Build Sequence 九步——(1) 该不该动，(2) 目的是什么，(3) 挑工具（一张很长的对照表 + 依赖表），(4) 挑属性，(5) timing 还是 spring，(6) 别跑在 JS 线程上，(7) 按压而非 hover，(8) haptics，(9) 减弱动效与无障碍；然后是三块工程细节：Setup that silently breaks motion（"动画就是不跑"时先查这些）、120fps、Never Ship 表（17 行）、Output、Tone。
- **`RECIPES.md`（385 行）**——可开工实现：先给所有配方共用的 setup（`GestureHandlerRootView`、共用 import、三条 `Easing.bezier` 常量）、三个全局约定（`.get()`/`.set()`；`scheduleOnRN` 取代 `runOnJS`；**手势要用 `useMemo` 包住**，每帧重建手势会重新挂载识别器并把进行中的拖拽丢掉）、Gesture Handler v3 的迁移写法；然后是两个到处都要用的 worklet——`project()`（Apple 的指数衰减式动量投影，**不是**物理课的 v²/2a）和 `rubberband()`（超出边界后跟随量递减）。配方包括：Press feedback、Bottom sheet you can drag to dismiss、Swipe to delete a row、Collapsing header on scroll、List entrances、Keyboard-synced UI、Tab/segmented indicator、Screen transitions (Expo Router)、Toast、Firing something once at a threshold。

工具选择表里几处值得记住的默认答案：**屏幕到屏幕**用 Expo Router 的原生 stack 选项，**永远不要手搓**；一个自成目的地的 bottom sheet 直接用 `presentation: 'formSheet'`（它就是真正的 `UISheetPresentationController`）；标签栏用 `NativeTabs`（`expo-router/unstable-native-tabs`）；上下文菜单/长按预览用 `Link.Menu` / `Link.Preview`（仅 iOS）；大标题折叠用 `headerLargeTitleEnabled`（`headerLargeTitle` 已废弃），**不要**用滚动 worklet；下拉刷新用 `RefreshControl`；跟键盘的 UI 用 `react-native-keyboard-controller`。并且明确了「连续或可打断的值才用 shared value」——**按压缩放是 CSS transition，拖拽才是 shared value**；用 worklet 做两态开关，等于在移动端为一次淡入装一个动画库。

## 注意事项与已知限制

- **`Never Ship` 是硬红线**（17 条），包括：`PanResponder`（改用 `Gesture.Pan()`）；手势/滚动回调里的 `setState`；`runOnJS`（Reanimated 4 已废弃，用 `scheduleOnRN`）；每帧 `scheduleOnRN`；渲染期读写 shared value；手指碰的东西用核心 `Animated`；动 `height`/`width`/`margin`/`flex`/`top`；动 `BlurView` intensity 或 Android `elevation`（改为交叉淡入淡出一个静态层）；虚拟列表行上的 `entering`（改用容器或 `itemLayoutAnimation`）；用 JS 重建屏幕转场；标签之间滑动；UI 元素上的 `Easing.in(...)`；`scale(0)` 进场；只看距离的关闭阈值（应该是速度**或**距离）；边界硬停（应该是橡皮筋）；每帧一次或作为唯一反馈的 haptic；在 Expo Go 或模拟器里判断手感。
- **属性限制有唯一豁免**：绝对定位且没有子元素的元素（标签 pill、进度条填充）可以动 `width`——它脱离文档流，不会引起其他节点重排，而且能保住圆角，`scaleX` 会把圆角拉成椭圆。
- **`transform` 是数组且顺序有意义**：`[{ translateY }, { scale }]` 是先移后缩；反过来平移量也会被缩放。
- **触控目标最小 44×44pt（Android 48dp）**：视觉小于这个就加 `hitSlop`，不要去放大视觉。另外用 `pressRetentionOffset` 让手指轻微漂移不会取消按压。Android 水波纹只在 Material 风格应用里用，自研设计里两个平台用同样的缩放更统一。
- **Haptics 三条绝对规则**：与视觉同一帧（滞后会被读成故障）；**每个用户动作一次**（绝不用于滚动、绝不每帧、绝不用于用户没触发的进场动画）；**绝不作为唯一反馈**（很多用户全局关掉了触感，多数 Android 硬件也没有）；从 worklet 触发必须 `scheduleOnRN(Haptics.selectionAsync)`。
- **文字会缩放**：`allowFontScaling` 默认开启，任何在默认字号下量出来的高度在 200% 字号下都是错的——不要动画到硬编码高度，要用 `onLayout` 量，或者改为动 transform。
- **`Extrapolation.CLAMP` 不是可选项**：少了它，滚过阈值后 opacity 会继续变负，标题会在长列表底部以反向形式重新出现。
- **列表配方的两条硬约束**：`entering` 绝不能放在 `FlatList`/`FlashList` 等虚拟列表的行上（行会被回收，动画每次滚回视野都会重放，看起来像在闪烁）；进场动画是给用户主动等待的内容的，用户每天刷过去的列表应该本来就在那儿。
- **平台差异要写清楚**：Android 的 form sheet detents 上限三个（更长的数组在 iOS 正常、在 Android 静默截断）；`sheetGrabberVisible` 仅 iOS；Android 的 form sheet 不能承载原生 header 或嵌套 stack；`fitToContents` 需要内容有明确尺寸（`flex: 1` 的根节点没有固有高度）。
- 技能会**主动拒绝**：「这不该动」或「这需要真机才能告诉你对不对」是它认可的诚实答案。

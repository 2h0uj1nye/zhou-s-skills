# 苹果式设计（apple-design）

> 一句话：把苹果 WWDC 那套「界面要像真实世界里的东西」的动效与设计方法论，翻译成 Web 上能直接抄的 CSS/JS 数值和规则。

| 项目 | 内容 |
|---|---|
| 宿主 | DSH（Ubuntu 24.04 实测可用；技能正文为英文，不影响使用） |
| 外部依赖 | 零依赖。只讲原理和代码写法，不调用任何 CLI 或接口；示例用到 `motion`（Framer Motion 同名库）作为弹簧实现示例，但换别的弹簧库也行 |
| 产出 | 一份对话内的设计/实现指导：具体到弹簧参数（damping/response 数值表）、动量投影公式、`backdrop-filter` 代码、排版数值、无障碍媒体查询 |
| 入选理由 | 模型默认写的是「固定时长 + CSS transition」这种不可打断的动画，正好是苹果方法最反对的做法。这个技能给出了一整套可执行的具体数值（比如抽屉 `damping 0.8 / response 0.3`、投影公式 `(v/1000)·d/(1−d)`），这些是模型本来不会主动说出来的 |

## 它解决什么问题

多数 Web 界面的动效是「预先写死的一段动画」：点一下，播放 300ms 的 transition，期间用户干不了别的。苹果的观点是这根本不叫行为，叫播放录音。技能里反复强调的核心是：**当动效从屏幕上的当前值出发、继承用户的手指速度、把动量投影到终点、并且随时能被抓住反悔时，界面才「活」**。所以它把「可打断性」称为最重要的一条原则，并且明确说：不要用 CSS transition 和 `@keyframes` 做任何手势驱动的东西——它们中途抓不住。

具体到做法，它给了一套顺序化的工作法。先是响应：反馈要在 `pointerdown` 就发生，不是 `click`（技能原话是延迟一出现，「直接感」就跳崖式下跌），还要审查 debounce、人为计时器、以及移动端约 300ms 的点按延迟。然后是直接操作：拖拽必须 1:1 跟手，并且要尊重「抓在元素的哪个位置」，用 `setPointerCapture` 让指针移出元素后仍能继续跟踪，同时记录最近几个 `pointermove` 的速度历史，供松手时交接。

最实用的是它把苹果的物理参数抄了下来。苹果刻意把 mass/stiffness/damping 三件套换成两个设计师能理解的参数：**damping ratio**（1.0 = 临界阻尼、不弹；<1.0 会过冲）和 **response**（秒，越小越干脆，并且它不是「时长」）。技能给了一张出厂值表：移动/重定位 `1.0 / 0.4`，旋转 `0.8 / 0.4`，抽屉/面板 `0.8 / 0.3`。默认策略是「全部用 damping 1.0」，只有当手势本身带动量（甩、抛、拖拽松手）时才加回弹（damping ~0.8）——菜单淡入还弹一下是错的，被你甩出去的卡片弹一下才是对的。

它还给了动量投影的确切函数，并特别指出物理教科书里的 `v²/(2·decel)` **不是**苹果实际用的：要用指数衰减形式 `(v/1000)·decelerationRate/(1−decelerationRate)`，`decelerationRate ≈ 0.998` 是正常滚动手感、`0.99` 更脆。此外覆盖了橡皮筋边界阻尼公式、进出同路径的空间一致性、方向暗示、材质与层次（半透明层、越大越厚、不要叠两层浅色半透明）、触感/声音三原则（因果、同帧、有节制）、减弱动效等三组无障碍媒体查询、以及光学字号/字距/行高随字号变化。

最后它把这一切挂在苹果的八条设计原则上（Purpose、Agency、Responsibility、Familiarity、Flexibility、Simplicity、Craft、Delight），让你在讨论「该不该做/该不该弹确认框」时有共同词汇。

## 什么时候该用它

- 「我想把这个抽屉做得像 iOS 那种跟手的感觉」
- 「卡片拖拽松手后应该飞到哪里？怎么算落点？」
- 「这段动效能不能中途被打断反悔？」
- 「怎么用 CSS 做苹果那种毛玻璃导航栏？」
- 「按钮点下去的反馈为什么感觉迟钝？」
- 「帮我按苹果的标准审一下这个交互动效」

## 什么时候别用它

- 要更泛化的「界面打磨 + 动效决策」心法时，用 `emil-design-eng`（本系列主技能）。
- 要对已有动画代码做分级审计、产出修复路线图时，用 `improve-animations`；要严格评审单个 diff 用 `review-animations`。
- 要主动在代码库里找「该动却没动」的地方时，用 `find-animation-opportunities`。
- 做 React Native / Expo 上的动画时用 `animate-expo`（本技能是翻译到 Web 平台的）。
- 只是想知道某个效果叫什么名字时用 `animation-vocabulary`。

## 内部结构

单文件技能：只有一个 `SKILL.md`（约 292 行），没有伴生文件。内容分两大块：

- **前言与核心观念**：开场白、知识来源、贯穿全文的一句话（动效从当前值出发 → 继承速度 → 投影动量 → 随时可抓可逆）。
- **17 个编号小节**：1 响应（杀延迟）、2 直接操作（1:1 跟手）、3 可打断性（最重要原则，含 `presentation value`、速度混合、2D 拆成独立 X/Y 弹簧）、4 用弹簧而非动画（damping/response 参数表 + 出厂值表）、5 速度交接（含相对速度归一化公式）、6 动量投影（含确切函数）、7 空间一致性、8 方向暗示、9 橡皮筋边界、10 手势细节清单（点按/拖拽/并行识别/双击延迟）、11 帧级顺滑（运动模糊、只动 `transform`/`opacity`、`will-change`）、12 材质与深度（7 条，含背板模糊、层次、vibrancy、滚动边缘效果、materialize 而非 fade）、13 多模态反馈三规则、14 无障碍（三个独立 media query）、15 排版（字距随字号、行高反向、Dynamic Type、系统字体优先）、16 八条设计原则 + 4 条战术规则、17 流程。
- **结尾 `Quick Reference` 表**：15 行「需要什么 → 技术 → 具体数值」，是整篇的速查索引。

之所以是单文件：它是一份方法论而非工作流，切片反而会破坏「先响应、再跟手、再可打断」的因果顺序。

## 注意事项与已知限制

- 硬性主张：**手势驱动的东西不要用 CSS transition / `@keyframes`**；只有「没有布局依赖的独立元素」（如 picker 高亮条）才允许例外。
- 中断重启动画时**必须从 presentation（屏幕当前）值开始**，从逻辑/目标值开始会看到跳变。
- 方向反转时要**混合速度而不是硬切**，否则会出现「撞墙」的速度不连续。
- 2D 运动要拆成独立的 X、Y 弹簧，单个 2D 弹簧会在 X/Y 速度不同时失步。
- **不要叠两层浅色半透明面**，可读性会崩塌。
- 减弱动效不等于没有反馈：要用短交叉淡入淡出替代滑动/弹簧，保留有助理解的不透明度与颜色变化。
- 开场白规则是硬性的：无具体问题时只回那一句，不得附带其他信息。
- 技能只给指导，不改代码；具体落到你的仓库里由你（或模型）执行。

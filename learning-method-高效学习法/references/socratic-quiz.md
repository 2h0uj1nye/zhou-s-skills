# 苏格拉底式测验方法

## 核心思想

通过「一问一答」的方式检验理解，当场纠正错误，填补盲区。

## 测验流程

```
开始 → 从简单问题问起 → 用户回答 → 评分+反馈 → 解释盲区 → 下一题（更难）→ 重复 5 题 → 总结
```

## 评分标准（每道题满分 10 分）

| 维度 | 权重 | 说明 |
|------|------|------|
| 正确性 | 40% | 核心答案是否正确 |
| 完整性 | 30% | 是否遗漏了重要细节 |
| 表达清晰度 | 20% | 解释是否清楚、有条理 |
| 深度 | 10% | 是否触类旁通、举一反三 |

## 反馈模板

```
【评分】X / 10

【哪里对】
- 你正确指出了...
- ...这部分理解很到位

【哪里错】
- ...的理解有误，实际上...
- 你漏掉了...这一点

【哪里不完整】
- 你还可以补充...
- 如果考虑到...会更全面

【重新解释你没掌握的部分】
（用更通俗/不同角度重新讲解用户没掌握的概念）
```

## 题目设计原则

### 数量
- 每次 5 道题

### 难度梯度
- 第 1 题：该主题最基础的概念（建立信心）
- 第 2-3 题：中等难度，检验核心理解
- 第 4 题：综合应用或常见陷阱
- 第 5 题：高阶/开放性问题（检验真实水平）

### 题目类型
概念识别 → 代码预测 → 找错改错 → 场景应用 → 综合设计

## 触发时机

1. **学完一个等级后** — 检验该等级是否掌握牢固
2. **用户主动要求** — 「考考我」「帮我测试一下」

## 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| 所有题目都太难 | 打击信心 | 第 1 题必须是最简单的概念 |
| 只判断对错不给反馈 | 用户不知道哪里错 | 必须用反馈模板逐项说明 |
| 题目过于碎片化 | 无法检验系统性理解 | 每道题对应一个核心概念，且有梯度 |
| 漏掉「重新解释」环节 | 用户还是不懂 | 反馈模板最后一项必须有 |

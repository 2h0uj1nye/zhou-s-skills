# 坑点与失败处理（实战踩坑记录）

只收录**真实踩过的坑**。这些是四份旧技能合并后仍然有效的部分。

## 1. 合并版并发写入防线 ⚠️ 最重要

知识库可能被**多个 agent / 会话并发维护**。实测出现过多次 “modified by sibling subagent” 警告，并产生过：

- 两个“模块十六”
- 重复编号 93
- **一条已写好的合并版条目被覆盖丢失**

处理规则：

1. 出现并发警告时：**立即重读整个文件**（不是局部、不是凭记忆），确认最新编号与模块序号。
2. 自己已写的条目若丢失 → **重新补上**，并重新 overwrite 上传飞书。
3. 编号**一律从重读后的最新尾部接续**，不要凭会话记忆。
4. 附录统计表每行结构相似：**一次只改一行**，且带足上下文（含相邻行）；改完核对全部计数（concepts / sops / cases / faqs / snippets / 视频知识点整理）。
5. `ops-log.jsonl` 必须**追加**（`Add-Content` 按 UTF-8 写），**禁止整文件重写**——整写会覆盖他人日志。
6. 更新合并版前必须先**完整读取**（不带 offset/limit），局部读完后直接整文件覆盖会导致编号段重复。

## 2. 附录统计是“伪表格”——patch 格式坑（实测）

- 合并版末尾“附录：知识库元信息”**不是 Markdown 表格**：每个字段独占一行，形如
  `cases` / 空行 / `20` / 空行 / `踩坑复盘`（**无 `|` 分隔符、无表头**）。
- 若用**带 `|` 的表格样式**写匹配串，模糊匹配会照常命中并把 `|` 写进文件 → 附录格式损坏（实测：`cases` 段被改成 `| cases\n|\n|21`，残留竖线）。
- **规则**：修改附录计数时，匹配串用**纯文本精确行、不带 `|`**，例如以 `cases`、空行、`20`、空行、`踩坑复盘` 为一段；修改后**必须完整读取核对**附录段无 `|` 残留。
- 更新合并版的完整核对清单：头部笔记总数、覆盖主题末尾追加、末尾新增模块编号接续最新值、附录各模块计数、无 `|` 残留。
- 本地改完还要确认 `_飞书备份.md` 同步——**备份文件是独立副本，不会自动同步**。

## 3. 其他合并版坑

| 坑 | 原因 | 对策 |
|----|------|------|
| 编号断档 | 未读合并版末尾就编号 | 先完整读取最后一条编号，再接续 |
| 编号重复 | 多次局部替换、未完整读取，导致编号段重复写入 | 改前完整读取，改后验证无重复再上传 |
| patch 匹配失败 | 附录带空行格式 | 匹配串原样带空行；先完整读取确认格式 |
| 覆盖丢失内容 | 先局部读取再整文件写入 | 整文件写入前必须先完整读取 |

## 4. Windows PowerShell 5.1 陷阱

### 4.1 exit_code 不可靠

Windows PowerShell 5.1 对许多命令（`Get-ChildItem`、`Measure-Object` 等）返回 `exit_code=1`，但命令**实际已成功执行**。

- **判断方式**：看**输出内容**，不要只看退出码。
- 能用 Python 或直接读写文件的，就不要绕 PowerShell。

### 4.2 中文脚本编码

- PowerShell 脚本含中文字符、保存为 **UTF-8 无 BOM** 时会报解析错误 / 乱码。
- 解决：含中文的 `.ps1` 保存为 **UTF-8 with BOM**；或优先用 Python 处理中文（`scripts/classify_notes.py` 即为纯 Python、避免该问题）。
- 处理中文文件名时，优先用 Python（`pathlib` + `encoding='utf-8'`）而不是 PowerShell 管道。

### 4.3 可安全使用的命令

- `Add-Content` → 追加日志（务必按 UTF-8）
- `python script.py` → 执行 Python 脚本
- `Test-Path` → 检查文件是否存在
- `Start-Process "<url>"` → 打开链接（第 1 步人工观看用）

## 5. 飞书 API 限制

- 飞书 Wiki API **不支持直接移动 / 重分类文档**。
- 只能"删除旧节点 + 创建新节点"，风险高（丢历史、丢权限、丢链接）。
- **结论**：本地与飞书**分别维护**，靠 `new` / `overwrite` 保持内容一致；不要试图镜像目录结构。
- 细节与失败处理见 `references/feishu.md`。

## 6. 外部依赖缺失时的退路

本技能依赖三个本机外部资源（**均不在技能包内**）：

| 依赖 | 缺失后果 | 退路 |
|------|----------|------|
| `kb-targets.json`（节点配置） | 无法定位飞书目标节点 | **停等**：请用户补齐配置；不要猜 node、不要用记忆里的旧值 |
| `upload_to_feishu.py`（上传脚本） | 无法上传飞书 | 本地照常完成第 3–4 步并写 ops-log；明确告知"飞书未同步"及缺失路径；**不得伪造上传成功** |
| `feishu-api.ps1`（token 刷新） | token 过期后无法自动刷新 | 请用户手动重新授权，或改用脚本内置的刷新逻辑 |

原则：**本地结果是主产物，飞书同步是可失败的附加步骤**。同步失败不回滚本地，也绝不谎报成功。

## 7. 其他流程坑

| 坑 | 原因 | 对策 |
|----|------|------|
| 视频蒸馏输出变成了给用户的回答 | 把压缩键值格式直接当回复 | 先给可读蒸馏输出，再入库 |
| 凭记忆编造视频内容 | 只有链接却假装看过 | 只有链接时**必须停等**人工观看/提供转写 |
| 路径写错 | 误以为根目录是 `D:\AI知识库` | 正确根目录是 `D:\AI云文档\AI知识库\AI学习知识库\` |
| 合并版路径陈旧 | 2026-08-12 整理后已从根目录移入 07 专题 | 用 `...\07-知识管理与蒸馏\知识库合并版（AI引用专用）.md` |
| 误删知识笔记 | 直接对已有文件做删除/覆盖 | 删除/覆盖前**先列出待删文件让用户确认**；只读/新增可自动执行 |
| 摄入隐私内容 | 转写含手机号、账号、聊天记录 | 入库前提示用户并**脱敏** |

## 8. 并行优化

- 节点创建 + 内容写入：不同文档**可并行**
- FAQ 更新、合并版更新：**必须串行**（先本地改完再 overwrite）
- 本地写入（第 3 步）与蒸馏输出（第 2 步）可同步进行

# 原子笔记格式与内容标准

本文件是 `kb-sync` 第 2、3 步的细则：蒸馏成什么样、拆成什么样、写成什么样。

## 1. 蒸馏内容标准（多多益善，详细充实）

1. **识别主题与领域**：AI 工具 / 方法论 / 国学 / 心理学 / 编程……
2. **拆出核心知识点并去噪**：广告、寒暄、“复制此链接”“点赞关注”等一律剔除
3. **每个知识点按四层展开**：
   - **深层逻辑解析**：不只讲表面意思，挖到底层机制
   - **现代科学对应**：关联心理学、社会学、神经科学、经济学等现代理论
   - **应用策略**：短期策略 + 长期策略，分场景给具体做法
   - **实战指南**：每日反思、决策检查清单、筛选流程等可操作内容
4. **相关笔记关联**：用 `[[文件名]]` 链接知识库中已有笔记
5. **呈现方式**：概念类给定义、方法类给步骤、案例类给"背景 → 行动 → 结果 → 经验"；用表格或分组
6. **一句话总结**：每篇必须有
7. **标注来源链接**：视频/文章链接（如有）

### 扩写原则

- 每条内容独立成节，**不压缩合并**
- 传统智慧类内容展开 20–28 条，每条包含：原文 → 表层含义 → 深层逻辑 → 江湖启示 → 现代对应 → 应用策略
- 避免简略输出，宁可多写不可少写

## 2. 原子化拆分原则

- **一篇只讲一个知识点**
- **结论先行**：第一句给核心定义或结论
- **交叉链接**：用 `[[文件名]]` 链接相关笔记
- 相互关联的要点（如九律）**保持单篇**，不强行拆分
- 总览类笔记必须保留，作为入口
- 方法论 / 分步骤流程类内容归入 `sops`
- 踩坑 / 盲点 / 反驳 / 失效场景归入 `cases`

### 模块归属判定

| 内容类型 | 模块 |
|----------|------|
| 概念定义、知识点 | `concepts` |
| 分步骤操作流程、方法论 | `sops` |
| 踩坑、盲点、反驳、失效场景 | `cases` |
| 问答汇总 | `faqs` |
| 快捷键 / 命令速查 | `snippets` |

## 3. 单篇笔记文件格式

```markdown
# 元认知

> **模块**：concepts
> **主题**：认知科学 / 个人成长
> **最后更新**：2026-08-09
> **复核周期**：长期

正文（结论先行，按四层展开）……

## 相关笔记
- [[让大脑更聪明的11个方法]]
- [[N-Back工作记忆训练]]
```

- 文件名：中文短语、语义清晰、无特殊字符；同主题加前缀（如 `GitHub下载资料流程.md` / `GitHub下载注意事项.md`）
- 结构统一：标题 → 模块头（模块/主题/最后更新/复核周期）→ 正文 → 相关笔记
- 可选元数据：frontmatter 中的 `tags` / `topic` / `version` / `status`

## 4. FAQ 文件格式

- FAQ **不新建文件**，追加到既有 FAQ 文件（思维方法论类 / 软件下载安装类 / 编程工具使用类）
- 文件头保留：模块 `faqs` / 主题 / 最后更新 / 复核周期：季度复核
- 追加格式：

```markdown
Q：让大脑变聪明，有没有具体可执行的方法？
A：有，核心是"适度挑战 + 充分恢复"：……
依据：[[让大脑更聪明的11个方法]]、[[睡眠周期与睡眠时长选择]]
```

- 追加后**必须更新文件头 `最后更新` 日期**；问答之间空一行（以文件现状为准，不要擅自引入 `---`）

## 5. 合并版单篇条目格式（新增批次用）

```markdown
77. 元认知
模块：concepts | 主题：认知科学 / 个人成长 | 最后更新：2026-08-09 | 复核周期：长期
定义: 对自己思维过程的监控与调控，即"思考自己的思考"；类比是开车时副驾驶看路况查导航
重要性: 能及时发现思维偏差，在错误结论形成前纠正
```

- 编号 `N. 标题` 连续递增，接续合并版当前最大编号
- 下一行为元信息：`模块：X | 主题：Y | 最后更新：日期 | 复核周期：Z`
- 正文为**压缩键值格式**：`字段名: 内容` 一行一条，多条并列用 `/` 分隔（早期条目是完整 markdown，视频蒸馏类从模块十三/十四起用键值压缩，与相邻批次保持一致）
- 条目之间空一行

## 6. 压缩格式 ≠ 给用户的回答

第 2 步产出的是**可读蒸馏文本**（标题、分段、说明）。压缩键值格式只用于合并版条目。
把键值行直接当回答发给用户，是已知的错误做法。

## 7. 命名与重复检查

- 新建前先确认知识库中没有同名或高度同义的笔记，避免重复入库
- 同主题的补充内容优先**追加到已有笔记**，而不是新建近义文件

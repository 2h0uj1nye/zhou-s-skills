# AI 知识库同步（kb-sync）

> 一句话：你把一段视频转写或一堆学习笔记丢给它，它整理成一篇篇讲单一知识点的笔记存到你电脑上，再帮你同步到飞书上的知识库。

| 项目 | 内容 |
|---|---|
| 宿主 | **Windows 专用**。路径写死在 D 盘，脚本走 PowerShell，同步的是飞书 Wiki |
| 外部依赖 | 需要本机三样东西：配置文件 `kb-targets.json`（必填，存飞书节点标识）、上传脚本 `upload_to_feishu.py`（必填）、`feishu-api.ps1`（可选，自动刷新登录凭证）；本机需有 python3 |
| 产出 | 本地笔记 .md 文件、合并版大文件的新条目、飞书节点链接或覆盖成功确认、一条运行日志 |
| 入选理由 | 清单里唯一真正「动手改你本地文件 + 对接外部服务」的落地型技能，把从内容到归档的一整条链路跑通，还带了防并发写坏的实战经验 |

## 它解决什么问题

看完一个讲得好的视频，转写文字躺在剪贴板里，最后不是丢了就是堆成一篇谁也不会再看的长文。手动归档更麻烦：要起文件名、要判断归属专题、要更新那份巨大的合并版、要记得编号接到多少、最后再贴到飞书上。这个技能把这串活串成一条固定流水线：蒸馏去噪 → 拆成一篇只讲一个知识点的笔记 → 落到对应专题文件夹 → 更新合并版并接续编号 → 上传飞书 → 记一条日志。它只管这一条链路，视频下载和转写不归它管。

## 什么时候该用它

- 「这是这条视频的转写，帮我整理进知识库。」（直接把文本贴上来）
- 「这是我今天记的学习笔记，整理入库。」
- 「把这条同步到飞书。」或「合并版更新一下，我这两天攒了几篇。」
- 「这份读书笔记帮我拆成知识库里的笔记，别搞成一大篇。」

## 什么时候别用它

- 你只是想让它看看、评价或总结这个视频，没有入库的意思——直接问就行，它不上手改文件。
- 你只想改飞书那边的文档结构、把飞书里的文档挪到另一个分类——飞书接口不支持移动文档，本技能做不了，得在飞书里手工删了重建。
- 你只要下载视频或只要把语音转成文字——那属于视频下载 / 转写类技能，拿到内容后再回到这里。
- 你只想讨论内容本身（提问、改写、扩写），不涉及存盘和同步。

## 怎么开口

- 「这是这条视频的转写，帮我整理进知识库。」
- 「这段笔记执行整理，归到合适的专题。」
- 「整理完顺便同步到飞书，告诉我链接。」

## 输入 / 输出

**它向你要**：视频链接 + 转写文本、纯文本笔记或 .md 文件、读书笔记 / 课程大纲这类结构化骨架。只有链接没有转写时，有一个明确的人工停等点，要你提供内容。

**它给你什么**：

1. **原子笔记 .md**：写进本地知识库对应专题文件夹，每篇只讲一个知识点、结论先行，含标题 + 模块头 + 正文 + 相关笔记链接；FAQ 不新建文件，而是追加到原有 FAQ 并更新文件头日期。
2. **合并版新增条目**：编号接续当前最大值、条目数 +N，文件头的版本日期与总数一并更新。
3. **飞书同步结果 + 运行日志**：新建返回节点号和链接，覆盖给成功确认，失败说明原因与退路、不谎报成功；同时向 `ops-log.jsonl` 追加一行本次事件记录。回报内容含新增笔记清单、FAQ 新增问答数、知识库总数、飞书状态、沉淀经验条数。

## 依赖与前提

- **操作系统**：Windows，路径写死为 `D:\AI云文档\AI知识库\...`（真正的根目录是 `AI学习知识库\`，不是 `D:\AI知识库`）。
- **必填配置**：`D:\AI云文档\AI知识库\config\kb-targets.json`，存飞书空间 ID、各节点的 node token 和文档 ID；缺了或解析不了就停下来让你补齐，**不会凭记忆猜节点**。
- **必填脚本**：`D:\AI云文档\AI知识库\scripts\upload_to_feishu.py`（在技能包外）；可选 `feishu-api.ps1` 用于自动刷新凭证（飞书凭证约 2 小时过期）。本机需有 python3 + PowerShell，脚本本身不需要第三方库；只有最后同步飞书那一步要联网，上传失败本地结果照常保留、不回滚。

## 内部结构

- `SKILL.md` 186 行：触发与排除场景、输入输出、路径与配置、七步主流程（每步标自动还是人工、完成标志与失败退路）、高频坑点、收尾自查清单。
- `references/` 四个文件共 376 行：`note-format.md`（102 行，笔记格式与蒸馏标准）、`topic-taxonomy.md`（79 行，10 个专题与归类规则）、`feishu.md`（99 行，配置结构/上传命令/失败处理）、`pitfalls.md`（96 行，真实踩坑记录）。
- `scripts/classify_notes.py` 267 行：**可直接运行的归类脚本**，按关键词把知识库根目录的 .md 笔记归入 10 个专题；只用 Python 标准库，**默认只预演不移动文件**，必须显式加 `--apply` 才真的动文件，还支持 `--report` 输出计划、`--json` 给程序消费；归不了类的只列出来交给人处理。

这样拆的原因：主文件管流程和判断，references 分别管「写成什么样 / 归到哪 / 怎么传 / 别踩哪些坑」，而归类这种重复劳动直接写成脚本——用 Python 而不是 PowerShell，正是为了绕开中文编码那个坑。

## 注意事项与已知限制

- **凭据已全部移出技能包**：飞书空间 ID、节点和文档标识一律从本机配置文件读取，包内文件里这些值都是 `<node_token>` 这样的占位符（实测全文扫描无任何真实凭据）。配置文件本身**不进技能包、不随包分享**——你要把技能包发给别人时，务必确认没把 `kb-targets.json` 一起打包。
- **合并版可能被并发写坏，且末尾附录不是真表格**：知识库可能被多个会话同时维护，实测出现过「modified by sibling subagent」警告、两个「模块十六」、编号重复、以及一条已写好的条目被覆盖丢失，对策是发现警告就整文件重读、编号只看重读结果。附录则是每字段独占一行、中间夹空行、没有竖线的格式，用带竖线的表格样式去匹配会把竖线写进文件（实测踩过），必须用纯文本精确行去改，改完核对无竖线残留。
- **PowerShell 5.1 两个坑**：含中文的 .ps1 必须存为 UTF-8 with BOM，否则报解析错误；而且很多命令明明执行成功也返回退出码 1，判断成败要看输出内容而不是退出码。
- **飞书接口不支持移动文档**：只能删旧建新，会丢历史和权限，所以本地与飞书是分别维护、靠覆盖保持一致，不追求目录结构镜像。
- **不会假装看过视频，也不擅自覆盖**：只有链接没有转写时必须停等你提供内容；对知识库内已有文件做覆盖或删除前，会先列出待动文件清单等你确认（新增和只读操作才自动做）。转写含手机号、账号、聊天记录、住址等隐私内容时，入库前会提示脱敏。

## 来源

由 4 个知识库技能合并而来：**ai-kb-sync（v4.7）** + **kb-topic-classification** + **knowledge-base-operations** + **kb-organizer**。合并后只保留一条主链路（蒸馏 → 原子笔记 → 本地落盘 → 合并版更新 → 飞书同步 → 自进化日志），去掉了视频下载、转写、飞书文档结构重构，以及与知识库无关的通用笔记整理。`references/pitfalls.md` 开篇写着「这些是四份旧技能合并后仍然有效的部分」，可印证确实是四份合并；但四个旧技能的具体名字只出现在移交说明里，合并后的文件内没有逐一点名。**关于明文凭据**：移交说明提到原文件正文有明文的飞书空间 ID 和 16 组令牌，核实结果——包内现已彻底没有（`references/feishu.md` 只留一份配置结构模板，值全是占位符），所以「16 组」无法从当前文件复核；能核对的是该模板共暴露 19 个标识位（1 个空间 ID + 4 个节点 × 节点号与文档号 + 10 个专题节点），与 16 对不上，按「已移除」处理即可，不必以旧数字为准。

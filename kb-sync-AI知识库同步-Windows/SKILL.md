# kb-sync：知识库蒸馏与同步（Windows）

单一职责，只跑通一条链路：**内容蒸馏 → 原子笔记 → 本地落盘 → 合并版更新 → 飞书同步 → 自进化日志**。
不做视频下载与转写、不做飞书文档结构重构、不做与知识库无关的通用笔记整理。

## 触发条件与排除场景

**触发**（满足任一即启动，无需用户再说“整理／上传”）：

- 用户发来**视频链接 + 文字转写**，并要求入库
- 用户粘贴**学习笔记 / 每日记录 / 踩坑经验 / 工具心得**，要求整理入库
- 用户提供**结构化骨架**（读书笔记、课程大纲、文章框架），要求整理成原子笔记
- 用户说“执行整理”“把这条归入专题”“同步到飞书”“合并版更新一下”

**排除**（明确不要用本技能）：

- 只是让你**看 / 评价 / 总结一个视频**，没有入库意图 → 直接回答即可
- 只想**讨论内容本身**（问答、辩论、扩写），不涉及落盘与同步
- **纯手动整理笔记**：用户自己维护文件，只要建议、不要动文件
- 只要**改飞书文档结构 / 移动飞书节点** → 本技能受限，见 `references/pitfalls.md`
- 只要**下载视频**或**只要转写** → 用视频下载类技能，拿到内容后再回到本技能

## 输入

| 输入 | 形态 | 是否含人工步骤 |
|------|------|----------------|
| 视频链接 + 转写文本 | 纯文本 | 否 |
| 只有视频链接 | URL | **是**，需人工观看后提供转写 |
| 学习笔记 / 踩坑记录 | 纯文本或 .md 文件 | 否 |
| 结构化骨架文件 | .md / .txt（读书笔记、课程大纲、文章框架） | 否 |

前置检查：`D:\AI云文档\AI知识库\config\kb-targets.json` 是否存在且可解析（见“路径与配置”）。缺配置时先停等用户补齐，不要凭记忆猜节点。

## 输出

1. **原子笔记 .md**：写入本地知识库对应专题文件夹，文件存在且非空
2. **合并版新增条目**：编号接续最新值，条目数 +N，附录计数同步更新
3. **飞书同步结果**：新建节点返回的 node 号／链接，或 overwrite 成功确认；失败则给出明确原因与退路
4. **ops-log.jsonl 追加行**：本次运行的事件记录（JSON 可解析）

**安全红线**：

- 飞书**空间 ID、节点 node token、文档 doc token 一律从 `kb-targets.json` 读取**，正文与本技能包内任何文件都不得出现明文。
- 该配置文件**不进技能包、不随包分享**；本包内不含任何真实 ID／token。
- 蒸馏内容若含隐私（手机号、账号、聊天记录、住址、身份证等），入库前**提示用户并脱敏**后再写盘。
- 动手前先探查：确认实际目录结构与合并版当前编号，不要照搬记忆。

配置字段说明与示例结构见 `references/feishu.md` §配置。

## 步骤：七步主流程

每一步标注**自动**或**人工**，并给出完成标志与失败退路。

### 第 1 步：获取内容（部分人工）

- 有转写文本 → **自动**，直接使用。
- **只有链接、无转写 → 人工停等点**：抖音短链（`v.douyin.com`）、B站、YouTube 等分享链接用 `Start-Process "<链接>"` 打开默认浏览器，请用户观看后粘贴转写或口述要点。**不要假装看过视频，不要凭标题编造内容。**
- 用户明确要求下载／转写 → yt-dlp + 语音转写（先确认工具已安装）。
- 以上都不可行 → 停下来向用户索要内容。

✅ 完成标志：手上有**完整、非空**的转写文本，且能对应到具体来源链接。
失败处理：链接失效 → 请用户提供转写或换源；**不得虚构转写**。

### 第 2 步：蒸馏分析（自动）

按 `references/note-format.md` 的「内容标准」执行：识别主题 → 去噪（广告、寒暄、“复制此链接”） → 深层逻辑 → 现代科学对应 → 应用策略 → 实战指南 → 相关笔记关联 → 一句话总结 → 标注来源。

✅ 完成标志：产出一份**可读的蒸馏文本**，含“一句话总结”与来源链接。
⚠️ 不要把压缩键值格式直接当回答丢给用户：先给可读蒸馏版，再入库。

### 第 3 步：原子化拆分 + 本地落盘（自动；覆盖／删除需人工确认）

- 拆分原则与原子笔记格式见 `references/note-format.md`。
- 归入 10 个专题之一，规则与关键词表见 `references/topic-taxonomy.md`；可先用 `scripts/classify_notes.py` 做 **dry-run** 预演归类。
- 新笔记文件名：中文短语、语义清晰、无特殊字符；同主题加前缀区分。
- FAQ **不新建文件**，追加到既有 FAQ 文件并更新文件头 `最后更新` 日期。

✅ 完成标志：笔记文件存在且非空，含标题 + 模块头 + 正文 + 相关笔记；对应专题文件的笔记清单**追加一行**且数量 +1。
**人工停等点**：对知识库内**已有文件**做覆盖／删除前，先列出待动文件清单让用户确认。
失败处理：文件名冲突 → 加前缀而非覆盖；无法归类 → 暂存 `归档\待分类\` 并在回报中说明。

### 第 4 步：更新合并版（自动，必须串行）

1. **并发写入防线**：先用完整读取方式**重读整个合并版**（不截断、不带 offset/limit），确认最新模块序号与最大编号；出现 “modified by sibling subagent” 警告时立即**整文件重读**，自己丢失的条目重新补写。
2. 在“附录：知识库元信息”**之前**插入新批次章节，编号从重读后的最新值接续（不凭会话记忆）。
3. 头部 `版本` = 当天日期，`笔记总数` = 最新编号，新主题追加到“覆盖主题”末尾。
4. 附录统计是**伪表格**（每值独占一行、之间有**空行**、无 `|`）：patch 的 old_string 必须用**纯文本精确行、不带 `|`**。

✅ 完成标志：编号连续、无重复、无断档；附录各计数已核对（concepts / sops / cases / faqs / snippets / 视频知识点整理）；附录段无 `|` 残留。
失败处理：patch 匹配失败 → 不要强改，重读文件后用相邻行做上下文重试；本地改完还要确认 `_飞书备份.md` 同步（独立副本，不会自动同步）。

### 第 5 步：上传飞书（自动，依赖外部脚本）

命令形式、节点配置与参数说明见 `references/feishu.md`。**每次 overwrite 前先 `list` 确认节点真实存在。**

✅ 完成标志：脚本返回成功并给出 **node 号／链接**（新建）或 overwrite 成功确认，`list` 能查到该节点。
失败处理：

| 失败 | 退路 |
|------|------|
| token 过期 | 走 `feishu-api.ps1` 自动刷新；仍失败 → 请用户重新授权 |
| 节点 ID 失效 | 先 `list` 取实际存在的 node，再 overwrite；不要硬用旧 token |
| 上传脚本缺失 | **本地照常完成第 3–4 步并写 ops-log**；明确告知用户“飞书未同步”及缺失路径，**不得伪造上传成功** |
| 合并版被并发修改 | 回到第 4 步重读重写，再重新 overwrite |

### 第 6 步：自进化日志（自动）

- 用 `Add-Content` 按 UTF-8 **追加**到 `meta\ops-log.jsonl`（**禁止整文件重写**，会覆盖他人日志）：`error` / `decision` / `sop_update` 三类事件。
- 每个 `error` 若 `cases\` 无同类记录 → 生成案例笔记；知识库 ≥10 篇时生成 `meta\quality-report.md`。

✅ 完成标志：ops-log.jsonl 末尾新增本次记录行，JSON 可解析，未覆盖既有内容。

### 第 7 步：回报用户（自动）

新增笔记清单（文件名 + 模块）、FAQ 新增问答数、本地知识库总数、飞书同步状态（node 链接或失败原因）、本次沉淀经验条数。

## 坑点

完整清单与复现细节见 `references/pitfalls.md`。高频五条：

| 坑 | 一句话对策 |
|----|-----------|
| 合并版被并发修改，出现重复模块/编号 | 立即整文件重读，编号只看重读结果 |
| 附录是伪表格，patch 把 `|` 写进文件 | old_string 用纯文本精确行，改完核对无 `|` |
| PowerShell 5.1 中文脚本报解析错误 | 含中文的 .ps1 存为 **UTF-8 with BOM**，或改用 Python |
| PS 5.1 成功命令也返回 exit_code=1 | 看输出内容，不要只看退出码 |
| 飞书 API 不支持移动文档 | 本地与飞书分别维护，靠 overwrite 保持一致 |

## 验证

收尾逐项自查，任一未过不要宣称完成：

- [ ] 蒸馏输出先给了**可读版本**，不是压缩键值原文
- [ ] 每篇笔记**原子化**：一篇只讲一个知识点，结论先行
- [ ] 笔记文件**存在且非空**，含标题 + 模块头 + 正文 + 相关笔记
- [ ] 已归入 10 个专题之一，专题清单已追加且数量 +1
- [ ] 未新建 FAQ 文件，FAQ 是追加且文件头日期已更新
- [ ] **合并版已更新**：编号接续、无重复、无断档，头部日期与总数已改
- [ ] 附录各计数已核对，附录段**无 `|` 残留**
- [ ] `_飞书备份.md` 已同步（如仓库中存在该文件）
- [ ] 飞书上传**返回 node 号／链接**，或已明确说明未同步及原因
- [ ] `meta\ops-log.jsonl` 已**追加**本次记录（未覆盖他人内容）
- [ ] 回报中含新增清单、飞书状态、沉淀经验条数
- [ ] 包内与正文**无任何真实空间 ID／node token／doc token 明文**
